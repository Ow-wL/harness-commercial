## 3. 서버 코드 바꾸는 법

### 3-1. 서버 시작 때 한 번 (업종과 무관)
```python
from etl_boundary import DongAreas
AREAS = DongAreas("경계_인천_행정동.geojson", panel)    # panel = 패널_통합.csv
```

### 3-2. 업종별 비교 분포 (업종마다 한 번, 캐시)
```python
import config as C
from radius_demand import build_reference, radius_profile, customer_inputs

tcol = f"타겟_{업종명}"                     # 예: "타겟_PC방"
XC = [tcol, "총인구", "종사자수"]
popd = panel[["시군구명", "행정동명"] + XC].loc[:, lambda d: ~d.columns.duplicated()]

ref, dong_total = build_reference(shops, popd, code, 500,
                                  pop_col=C.DEMAND_COLS,           # 거주 + 종사자
                                  extra_cols=XC,                   # 고객성 반경 인구
                                  same_weights=C.same_weights(code),  # 대체업종
                                  areas=AREAS)                     # 면적 배분
```
⚠ 입지성 비교 분포를 캐시한다면 캐시 키에 **학교구역 여부**를 넣어야 한다. 키를 유인시설 목록만으로 잡으면 PC방(학교구역 적용)과 분식(미적용)이 같은 캐시를 써서 틀린다.
```python
from etl_location import _school_zoned
key = (tuple(C.ANCHOR.get(code, C.DEFAULT_ANCHOR)), _school_zoned(code))
```

### 3-3. 사용자가 지점을 찍을 때
```python
rp = radius_profile(lat, lng, shops, popd, code, 500, pop_col=C.DEMAND_COLS,
                    dong_total_shops=dong_total, extra_cols=XC,
                    same_weights=C.same_weights(code), areas=AREAS)
cust_dong, cust_panel = customer_inputs(rp, ref, tcol)

dong.update(cust_dong)           # target_pop·target_share·workers를 반경 값으로 덮어쓴다
panel_dict.update(cust_panel)    # 비교 분포도 반경 값으로
panel_dict["same_biz_share"] = ref["반경_동종비중"].fillna(0).tolist()

res = analyze(site, dong, panel_dict, [], [], [], cohort_counts,
              radius_profile=rp,
              radius_ref=ref.loc[ref["반경_동종점포"] > 0, "반경_점포당수요"].dropna().tolist(),
              agg_ref=ref["반경_전체점포"].tolist(),       # 상권 집적도
              loc_profile=lp, loc_ref=lref,
              schools=학교목록)                            # 학교구역 경고에 필요 (type·lat·lng)
```
그대로 따라 할 수 있는 예시는 `04_엔진코드/run_all.py`의 반복문 안쪽이다.

### 3-4. 안 바꾸면 어떻게 되나
| 빠뜨린 것 | 결과 |
|---|---|
| `areas` | 예전 점포 분포 배분으로 계산된다. 번화가 인구가 2배 이상 잡혀 점수가 v0.5와 다르다 |
| `agg_ref` | 집적도 지표가 '제외'로 처리된다(집적형 가점 없음) |
| `customer_inputs` | 고객성이 행정동 전체 값으로 계산된다(v0.4 방식) |
| `schools` | 학교구역 경고가 안 뜬다. 점수 쪽 학교 제외는 `etl_location`에서 되므로 그대로 적용된다 |

### 4-2. 경고 표시 규칙
- `경고[]`는 **전부 보여준다**(LLM 규칙과 같음). 순서는 엔진이 정한 대로 둔다.
- 학교구역 경고는 맨 앞에 들어온다. 문구가 `⚠`로 시작하니 **빨간색 강조**를 권한다.

### 4-3. 이름이 같지만 뜻이 바뀐 항목
| 키 | v0.3 | v0.5 |
|---|---|---|
| 고객성 `raw.타겟연령_거주인구` | 행정동 전체 | **반경 500m** (면적 배분) |
| 고객성 `raw.종사자수` | 행정동 전체 | **반경 500m** |

## 6. 발표·화면에서 밝힐 한계
- **점수 ≠ 성공 확률.** 사후 검증에서 점수와 실제 3년 생존의 상관은 0 근처였다(음식 9개 업종 평균 ρ −0.07).
- 방문 인구가 아직 없어 경쟁성은 번화가에 다소 불리하다(지오비전 퍼즐 대기).
- 업종 집적 계수와 역 의존도는 가설값이다. 집적 계수 일부(카페·한식·양식)는 인천 생존 분석으로 보정했다.
- 시장성·안정성은 구 단위, 임대료는 9개 상권 단위다.
- 행정동 경계는 2025년 2분기 기준이다(2026-07 개편 전). 행정동명으로 연결해 158/158개 동이 모두 연결됐다.
