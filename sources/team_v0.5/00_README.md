## 화면 연결 (3번 담당용)
엔진 호출: `scoring.analyze(site, dong, panel, ..., radius_profile=, radius_ref=, agg_ref=, user_weights=None, importance=None, user_licenses=None, schools=None)`

**v0.5:** 호출 방식이 바뀌었다. `00_팀원전달_정리본_v0.5.md` 3장을 따른다. (참고, v0.4 추가: `agg_ref` = 인천 158개 동 중심점의 반경 500m 전체 점포 수 목록(`build_reference()`의 `반경_전체점포` 열). 업종과 무관하므로 서버 시작 때 한 번만 만든다. 안 넣으면 집적도는 '제외'로 처리된다.)

결과 JSON 주요 항목 (`05_분석결과/업종별_상세JSON/full_PC방.json` 참고):
- `종합.점수`, `종합.병목_지표`, `종합.적용_가중치`
- `지표[]` — 5개 관점별 `score`, `confidence`, `breakdown`(세부지표별 점수·기여도·원시값)
- `경고[]` — 병목, 진입장벽, 학교 주변 규제 등
- (v0.4) 경쟁성 `raw.업종_집적유형`(집적형/중간형/근린형), `raw.상권_집적도_백분위`
- `초보자_접근성` — 제도 진입장벽(낮음/중간/높음)과 이유. **점수에는 반영되지 않는다**

사용자 조건 넣는 법:
- 중요도 슬라이더 1~5 → `importance={"stability": 5, "competition": 4}` (생략한 관점은 3)
- 가중치 직접 입력 → `user_weights={"market": 0.3, ...}` (합이 1이 아니어도 정규화)
- 보유 면허 → `user_licenses=["미용사(일반)"]`

## 현재 한계 (발표 때 밝힐 것)
- **점수 ≠ 성공 확률.** 사후 검증에서 점수와 실제 3년 생존의 상관은 0 근처였다(음식 9개 업종 평균 ρ: v0.4 −0.09, v0.5 −0.07).
- 방문 인구가 없어 경쟁성은 번화가에 다소 불리하다. 역 의존도·1인가구 민감도도 업종 성격으로 정한 가설값이다.
- 업종 집적 계수(α)는 업종 성격으로 정한 가설값이다. `validate_seoul.py`로 서울 데이터 검증 후 교체한다.
- 잠재수요에 방문 인구가 아직 없다(지오비전 퍼즐 API 연결 대기). 입력 칸은 만들어 두었다(`config.DEMAND_COLS`).
- 안정성은 13개 업종(PC방 + 음식 12개)만 계산된다. 미용·세탁·노래방 등은 인허가 파일을 받으면 채워지고, 편의점·슈퍼·요가(자유업)와 학원·독서실(교육청 소관)은 공공 인허가 데이터가 없다.
- 시장성·안정성은 구 단위, 임대료는 인천 9개 상권 단위다.
- 가중치는 실증되지 않았다(민감도 분석으로 결과가 가중치에 크게 흔들리지 않음을 보였다. v0.5: ±20% 0.97, ±50% 0.87).
- 분석 지점은 부평역 하나다.
- 점수는 인천 내 상대 순위이며 매출을 뜻하지 않는다.
