# 5대 관점 스코어링 로직 설계서 (MVP)

> 작성 2026-09-21 · 엔진버전 mvp-0.3 (2026-10-01: 세부지표 breakdown, 사용자 가중치 추가 · 2026-10-02: 초보자 접근성 태그, 음식 업종 안정성) · 레퍼런스 구현 `engine/` 동봉

---

## 0. 설계 원칙 5가지

이 다섯 개가 모든 세부 결정의 근거다. 논쟁이 생기면 여기로 돌아온다.

1. **엔진은 수치와 근거까지만 만든다.** 해석·행동제안은 LLM 담당. PPT의 역할 분리 원칙을 코드 레벨에서 강제한다.
2. **절대 매출액을 추정하지 않는다.** 인천에 행정동 단위 매출 원본이 없으므로 절대값 주장은 근거가 없다. **인천 내 상대 순위(백분위)로만 말한다.**
3. **점수와 원시값을 항상 같이 반환한다.** 백분위는 순위만 담고 격차를 못 담는다(1위와 2위가 10배 차이나도 1점 차). 격차는 원시값이 담당한다.
4. **데이터가 없으면 0점이 아니라 제외한다.** 결측을 0으로 처리하면 데이터 공백이 있는 지역이 부당하게 낮게 나온다. 해당 지표를 빼고 가중치를 재정규화한 뒤, 뺐다는 사실을 기록한다.
5. **모든 지표에 신뢰도와 폴백 레벨을 붙인다.** LLM이 이걸 읽고 말투를 조절한다. "~입니다" vs "~로 추정되나 표본이 적습니다"의 차이.

## 1. 분석 단위 — 하이브리드

사용자는 "부평역 근처 PC방"이라고 입력한다. 반경이 자연스럽지만, 인구·유입 데이터는 전부 행정동 단위다. 그래서 지표마다 단위를 나눈다.

| 관점 | 단위 | 이유 |
|---|---|---|
| 경쟁성 | **반경 500m** | 점포 좌표가 있으므로 반경이 정확. 행정동 경계는 실제 상권과 무관 |
| 입지성 | **반경 + 거리감쇠** | 역·학교 좌표 기반. 거리에 따라 연속적으로 감쇠 |
| 시장성 | **행정동** | 생활이동이 행정동 단위 |
| 고객성 | **행정동** | 주민등록인구가 행정동 단위 |
| 안정성 | **행정동 → 폴백** | 인허가는 좌표가 있지만 코호트 표본이 얇아 폴백 필요 |

반경이 여러 행정동에 걸치면 **면적 가중 평균**으로 합산한다.

## 2. 정규화 — 백분위, 단 모집단을 조심해서

모든 세부지표는 **인천 전체 행정동(N=158, 실측 확인) 분포 대비 백분위(0~100)** 로 변환한다.

```python
pct_rank(value, population, higher_is_better=True)
  → (population < value).sum() / N * 100
  → 표본 5개 미만이면 None (계산 거부)
```

**왜 z-score가 아니라 백분위인가:** 공공데이터 분포가 대부분 심하게 우편향(long tail)이라 z-score는 소수 번화가가 전체를 끌고 간다. 백분위는 분포 모양에 무관하고, 무엇보다 **사용자에게 설명하기 쉽다** — "인천 상위 18%"는 누구나 이해한다. 규칙 기반 스코어링의 목적이 설명 가능성이라는 PPT 주장과 일관된다.

## 3. 5대 지표 계산식

### 시장성 — 돈 쓸 사람이 오는가

| 세부지표 | 가중 | 데이터 |
|---|---|---|
| M1 일평균 유입인구 | 0.40 | 수도권 생활이동(도착지 기준) |
| **M3 시간대 적합도** | 0.30 | 생활이동 시간대별 × 업종 영업시간 |
| M2 **상권성격 적합도** | 0.20 | 생활이동 출근/귀가 (쇼핑 대체, 아래) |
| M4 군구 업종소비 전년비 | 0.10 | 인천e음 결제금액 |

**⚠️ M2는 실데이터에서 교체됐다.** 원래 '쇼핑목적 유입비중'으로 설계했으나, 인천 11개 구 중 쇼핑>0인 곳이 2개뿐이라 백분위가 성립하지 않았다.

대체 지표는 **상권 성격 적합도**다.
```
직장성   = 출근유입 / (출근유입 + 귀가유입)     인천 0.194(검단) ~ 0.365(제물포)
적합도   = 1 - |업종 선호 - 지역 직장성|        (둘 다 0~1 정규화)
```
업종별 선호는 `config.WORK_PREF`(-1 주거형 ~ +1 직장형). 백반/한정식 +0.7(점심 직장인), 입시학원 -0.8(학령인구 주거지). **"직장인 상권 vs 베드타운"은 상권분석의 기본 구분**이라, 쇼핑보다 오히려 본질에 가깝다.

**M3가 이 설계의 차별점이다.** 생활이동이 시간대별로 나오기 때문에 계산할 수 있다.

```
w_t = 업종 영업 가중 벡터 (24시간, Σ=1)
p_t = 행정동 시간대별 유입 분포 (Σ=1)
시간대_적합도 = Σ(w_t × p_t) × 24
```

**1.0 = 인천 평균, >1.0 = 내 영업시간에 사람이 몰림, <1.0 = 엇갈림.**

유동인구 총량이 같아도 카페와 호프집은 전혀 다른 결론이 나온다. 총량만 보는 기존 서비스가 못 하는 계산이고, **인천에 매출 데이터가 없다는 약점을 오히려 강점으로 뒤집는 지점**이다.

### 고객성 — 내 손님이 여기 사는가

| 세부지표 | 가중 | 비고 |
|---|---|---|
| C1 타겟연령 거주인구 (규모) | 0.35 | |
| C2 타겟연령 비중 (농도) | 0.30 | |
| C3 종사자 수 (직장인구) | 0.20 | SGIS 사업체통계 |
| C4 1인세대 비중 | 0.15 | 업종 민감도로 스케일링 |

**규모(C1)와 농도(C2)를 분리한 이유:** 둘이 엇갈릴 때가 진짜 정보다.
- C1 높고 C2 낮음 → `모수는_크나_타겟농도_낮음` (번화가지만 내 손님은 아님)
- C1 낮고 C2 높음 → `타겟농도_높으나_모수_작음` (틈새지만 파이가 작음)

C4는 업종별 민감도로 조정한다. 편의점(1.0)은 1인세대 신호를 그대로 반영하고, 한식(0.3)은 중립(50점) 쪽으로 끌어당긴다.

```
p4 = 50 + (백분위 - 50) × 민감도
```

### 경쟁성 — 파이 대비 경쟁자가 몇인가

| 세부지표 | 가중 | 방향 |
|---|---|---|
| **P2 점포당 잠재수요** | 0.50 | 높을수록 좋음 |
| P1 동종업종 비중 | 0.30 | 낮을수록 좋음 |
| P4 최근 1년 순증감 | 0.20 | 낮을수록 좋음 |

**⚠ 밀도만 쓰면 안 된다.** 점포가 많으면 나쁘다고 단순화하면 **카페거리·먹자골목 같은 집적 상권이 전부 최악으로 나온다.** 집적 효과(agglomeration)는 실재한다 — 사람들은 선택지가 많은 곳으로 간다.

그래서 주력 지표를 **점포당 잠재수요**로 잡는다.

```
잠재수요 = 유입인구 × 0.3 + 거주인구 × 0.7
P2 = 잠재수요 / 동종점포수
```

점포가 많아도 수요가 더 많으면 점수가 높다. 이게 "경쟁이 치열한 번화가"와 "수요 없는데 과밀한 동네"를 구분한다.

### ⚠️ 실데이터에서 발견한 결함 — 분자·분모 기준 불일치 (v0.2에서 수정)

반경 500m가 여러 행정동에 걸치면, **점포는 반경 기준으로 세면서 인구는 1개 행정동만 쓰는 비대칭**이 생긴다. 분석지점이 부당하게 불리해진다.

부평역 PC방 실측에서 이 차이가 **백분위 16 → 32로 두 배**였다.

**수정 — 점포밀도 면적가중(areal weighting):**
```
반경에 걸친 각 행정동 d에 대해
    w_d = (반경 내 d의 점포수) / (d의 전체 점포수)
    반경수요 = Σ_d  w_d × 인구_d
```
행정동 경계 폴리곤 없이 계산되며, 점포 분포를 '활동이 일어나는 곳'의 프록시로 쓴다. 경계 GeoJSON 확보 시 실면적 가중으로 교체할 것.

**비교 모집단도 같은 규칙으로 만든다.** 158개 행정동의 점포 중심점을 가상 분석지점으로 두고 동일 계산을 돌린다. 분석지점과 모집단이 같은 규칙으로 산출되어야 백분위가 유효하다. → `radius_demand.py`

부평역 실측: 4개 행정동에서 53,198명 배분(부평6동 w=0.807, 부평5동 0.542, 부평1동 0.517, 부평2동 0.123) ÷ PC방 12개 = 점포당 4,433명. 인천 중앙값 6,955명 대비 백분위 32.

**⚠ 동종점포 0개는 만점이 아니다.** 경쟁이 없는 게 아니라 *아무도 안 하는* 것일 수 있다. 수요가 없어서일 수도, 규제 때문일 수도, 진짜 틈새일 수도 있는데 **엔진은 이걸 판별할 수 없다.**

→ 이 경우 **점수를 매기지 않고(None) 가중치를 재분배**한다. 대신 수요 백분위를 근거로 넘기고 `미개척_동종점포_0개` 플래그와 최상위 경고를 세워, LLM이 양면 해석하게 한다.

> 초기 설계에서는 여기에 99점을 줬는데, 엣지 테스트에서 종합점수가 72.2로 부당하게 튀는 게 잡혔다. 지금은 64.6이 나온다.

### 입지성 — 올 이유가 있는가

| 세부지표 | 가중 |
|---|---|
| L2 역세권 강도 (승하차 × 거리감쇠) | 0.35 |
| L3 업종별 유인시설 근접도 | 0.35 |
| L1 최근접역 거리 | 0.20 |
| L4 버스정류장 밀도 | 0.10 |

거리 감쇠는 지수함수를 쓴다. `exp(-d / scale)` — 역세권 scale 400m, 유인시설 300m. 400m에서 0.37, 800m에서 0.14로 떨어진다.

L3의 유인시설은 **업종마다 다르다.** PC방은 중·고등학교와 학원, 카페는 오피스와 대학, 편의점은 아파트. 이게 "역 가까우면 무조건 좋다"는 단순 논리를 넘어서는 지점이다.

### 안정성 — 버틸 수 있는가

| 세부지표 | 가중 | 방향 |
|---|---|---|
| S1 3년 생존율 | 0.40 | 높을수록 좋음 |
| S2 최근 폐업률 | 0.25 | 낮을수록 좋음 |
| S3 평균 업력 | 0.20 | 높을수록 좋음 |
| S4 상권 임대료 ㎡당 (소규모상가) | 0.15 | 낮을수록 좋음 (2026-10-01 연결, 11장) |

인허가 데이터(인허가일자 + 폐업일자)로 코호트 생존율을 직접 계산한다.

```
2021년 인허가 집합을 분모로,
그중 (폐업일자 - 인허가일자) ≤ 1095일을 분자로 → 3년 폐업률
```

**실측 결과 (인천 PC방 4,701건, 2013년 이후 인허가 코호트)**

| 구분 | 1년 | 3년 | 5년 |
|---|---|---|---|
| 인천 PC방 전체 | 79.7% | 51.2% | 36.6% |
| 인천 전 업종 (시 공식통계) | 80.2% | 55.2% | 40.0% |

독립 계산인데 방향이 일치한다 — PC방이 전 업종보다 위험하다는 결과가 상식과 맞고, 공식통계와의 격차도 합리적이다. 산출 로직의 교차검증이 된다.

**⚠️ Censoring** — 2024년 인허가 업소는 아직 3년이 안 지났다. 분모에 넣으면 '아직 안 망했다'가 '3년 생존'으로 잘못 집계되어 생존율이 부풀려진다. N년이 경과한 코호트만 분모로 쓴다.

**⚠️ 종료 판정** — '폐업'뿐 아니라 '취소/말소/만료/정지/중지'도 실질적 종료다. 인천 기준 폐업 2,672 + 취소·말소 1,017이라 둘을 합쳐야 실태에 맞다.

기준선은 **인천시 소상공인통계의 생존율(1년 80.2% / 3년 55.2% / 5년 40.0%)** 을 쓴다. 인천시×경인지방통계청 공식 통계라 *"인천 공식 통계로 검증된 수치"* 라고 말할 수 있다.

## 4. 폴백 사다리 — 표본이 얇을 때

특정 업종이 인천 전체에 30개뿐이면 행정동별 폐업률은 통계적으로 무의미하다. 그런데 "데이터 없음"이라고만 하면 화면이 빈다.

**해상도를 한 단계씩 낮추되, 낮췄다는 사실을 반드시 기록한다.**

| 레벨 | 조건 | 신뢰도 |
|---|---|---|
| 행정동 × 소분류 | n ≥ 10 | high |
| 행정동 × 중분류 | n ≥ 10 | medium |
| 군구 × 소분류 | n ≥ 30 | medium |
| 인천 업종평균 | 무조건 | low |

이게 **"설명 가능한 스코어링"의 실체**다. 점수 하나만 던지는 게 아니라 "이 숫자가 어느 해상도에서 나왔는지"를 같이 넘긴다. LLM은 이걸 읽고 *"부평1동 PC방 표본이 3건뿐이라 부평구 전체 기준으로 계산했습니다"* 라고 말할 수 있다.

**추가로 `coverage`** — 세부지표 가중치 중 실제로 몇 %가 계산됐는지를 기록한다. 50% 미만이면 신뢰도를 두 단계, 80% 미만이면 한 단계 강등한다.

## 5. 업종 그룹별 가중치

업종마다 중요한 관점이 다르다. 전 업종 동일 가중치는 의미가 없다. 소분류 247개를 다 만들 수 없으니 **4개 그룹**으로 묶는다.

| 그룹 | 예시 | 시장성 | 고객성 | 경쟁성 | 입지성 | 안정성 |
|---|---|---|---|---|---|---|
| **A 고객밀착형** | 편의점·세탁소·미용실 | 0.15 | **0.30** | 0.20 | 0.15 | 0.20 |
| **B 유동인구형** | 카페·분식·베이커리 | **0.28** | 0.14 | 0.18 | 0.22 | 0.18 |
| **C 목적방문형** | PC방·스터디카페·학원 | 0.15 | **0.27** | 0.22 | 0.18 | 0.18 |
| **D 체류소비형** | 음식점·호프·주점 | 0.24 | 0.18 | 0.22 | 0.14 | **0.22** |

**안정성 가중치를 일반 상권분석보다 높게(0.18~0.22) 잡았다.** 타겟이 *1~3년차 폐업률 34.3%* 인 청년 예비창업자이기 때문이다. 기존 서비스가 "얼마 벌까"를 보여준다면, 이 서비스는 "버틸 수 있나"를 같이 본다. 이건 기술적 선택이 아니라 **제품 철학의 선택**이고, 숫자로 박아둔 것이다.

## 6. 종합점수 — 평균만으로는 부족하다

```
종합 = Σ(관점점수 × 그룹가중치), 결측은 제외 후 재정규화
```

**문제:** 평균 58점은 "무난"처럼 읽히는데, 실제로는 **네 개가 80점이고 안정성만 18점**일 수 있다. 창업자에게 이건 전혀 무난하지 않다.

**해결: 병목 탐지.** 최저 지표가 25점 미만이면 종합점수와 **별개로** 경고를 세운다.

실제 데모 출력:

```
종합 58.5점   (최고: 입지성 / 병목: 안정성)

시장성  81.8  ● 영업시간대_유입_집중
고객성  71.4
경쟁성  36.9  ● 신규진입_증가중
입지성  86.5  ● 역세권_300m내
안정성  18.0  ● 폐업률_높음

⚠ 안정성이 인천 하위 18%로, 종합점수와 별개로 단일 병목입니다.
```

**이 한 줄이 서비스의 존재 이유다.** "부평역 PC방 58.5점"은 아무 도움이 안 되지만, "입지와 유동인구는 최상위인데 이 동네 PC방 3년 생존율이 48%로 인천 하위 18%"는 의사결정을 바꾼다.

## 7. 엔진 → LLM 출력 계약

```jsonc
{
  "meta":  { "업종", "업종그룹", "행정동", "분석반경_m", "정규화_기준", "엔진버전" },
  "종합":  { "점수", "적용_가중치", "최고_지표", "병목_지표", "데이터_충족률",
            "가중치_출처",            // 기본(업종그룹) / 사용자(중요도 1~5) / 사용자(직접 입력)
            "기본_가중치",            // 업종그룹 기본값 (비교용)
            "기본가중치_종합점수",     // 사용자 가중치를 썼을 때만. 기본값으로 계산한 종합
            "중요도", "하한_적용" },   // 해당할 때만 포함
  "지표":  [ {
      "key": "stability",
      "label": "안정성",
      "score": 18.0,            // 0~100 백분위. null = 계산 불가
      "raw": {                  // ★ LLM이 문장에 쓸 실제 수치
        "3년_생존율": 0.48,
        "최근_폐업률": 0.22,
        "인천_업종평균_3년생존율": 0.552
      },
      "confidence": "high",     // high / medium / low
      "coverage": 1.0,          // 세부지표 중 실제 계산 비율
      "fallback": "dong_sobun", // 어느 해상도에서 나온 숫자인지
      "flags": ["폐업률_높음"],
      "note": "",
      "breakdown": [            // v0.2 추가: 세부지표별 근거. 기여도 합 == score
        { "key": "s1", "label": "3년 생존율", "score": 63.6,
          "설계_가중치": 0.40, "적용_가중치": 0.471, "기여도": 29.9,
          "원시값": 0.5541, "상태": "계산" },
        { "key": "s4", "label": "군구 임대료", "score": null,
          "설계_가중치": 0.15, "적용_가중치": 0.0, "기여도": null,
          "원시값": null, "상태": "제외(데이터 없음)" }
      ]
  } ],
  "경고": [ "안정성이 인천 하위 18%로 … 단일 병목입니다." ],
  "면책": "본 점수는 공공데이터 기반 상대 순위이며 매출을 보장하지 않습니다. …"
}
```

### LLM 프롬프트 규칙 (역할 분리 강제)

1. **`score`와 `raw`의 수치를 절대 변형하지 말 것.** 재계산·반올림·추정 금지
2. **`confidence`가 medium/low면 반드시 단서를 붙일 것** — "표본이 적어 참고용"
3. **`fallback`이 `dong_sobun`이 아니면 해상도를 명시할 것** — "부평구 전체 기준"
4. **`경고` 배열은 전부 사용자에게 전달할 것.** 생략 금지
5. **`flags`를 문장의 근거로 쓸 것.** 새 주장을 만들지 말 것
6. 출력 형식: **기회 1 / 위험 1 / 행동제안 3**

### Lv.2 경계선 (PDF 기획서와의 정합)

PDF는 "MVP는 Lv.2(인사이트 도출)까지, Lv.3(구체적 액션)은 책임 소재 이슈로 향후"라 했는데 PPT는 행동제안 3가지를 MVP에 넣었다. **행동제안을 조건부 정보 제시로 쓰면 둘 다 만족한다.**

| ❌ Lv.3 (단정) | ✅ Lv.2 (조건부 정보) |
|---|---|
| "부평2동으로 옮기세요" | "임대료가 ㎡당 30,775원으로 인천 상위권입니다. 인접한 부평2동은 22,400원입니다." |
| "PC방은 하지 마세요" | "이 동네 PC방 3년 생존율 48%는 인천 평균 55.2%보다 낮습니다. 최근 1년 2곳이 순증했습니다." |

**판단 동사를 쓰지 않고 비교 가능한 수치를 나란히 놓는다.** 결정은 사용자가 한다. 책임 소재 문제를 피하면서도 실질적으로는 더 유용하다.

## 10. 사용자 조건에 따른 유연한 점수 (v0.2, 2026-10-01)

"사용자 요구 조건에 따라 점수가 달라질 수 있다"를 규칙으로 못 박은 장이다. 점수 자체(백분위)는 그대로 두고, **관점 가중치만** 사용자가 바꾼다.

### 10-1. 3층 구조

| 층 | 내용 | 상태 |
|---|---|---|
| 1. 업종그룹 기본 가중치 | 5장의 A~D 4그룹 | 구현 |
| 2. 사용자 우선순위 | 관점별 중요도 1~5 또는 가중치 직접 입력 | **엔진 구현** (화면 미구현) |
| 3. 하드 제약 | 예산·타겟 연령 등 점수가 아닌 필터 | 미구현 (예산은 임대료·초기비용 데이터 필요) |

### 10-2. 규칙

| # | 규칙 | 이유 |
|---|---|---|
| R1 | 입력이 없으면 기본 가중치. 결과는 v0.1과 동일(29개 업종 회귀 검증) | 기존 동작 보존 |
| R2 | 가중치 합은 항상 1 (직접 입력은 합이 1이 아니어도 정규화) | 비교 가능성 |
| R3 | 관점당 최소 5%(`MIN_WEIGHT`). 낮은 쪽을 5%로 올리고 나머지를 비례 축소 | 관점을 통째로 숨기지 못하게 |
| R4 | 잘못된 입력(알 수 없는 관점, 음수, 중요도 1~5 밖, 모두 0, 두 방식 동시 사용)은 조용히 보정하지 않고 오류 | 사용자 의도를 임의로 바꾸지 않음 |
| R5 | **병목 경고는 가중치와 무관하게 점수만으로 판정**. 병목 관점 가중치를 기본보다 낮췄다면 그 사실도 경고에 덧붙임 | 가중치를 낮춰 위험을 지우는 것 방지 |
| R6 | 사용자 가중치를 쓰면 기본 가중치 종합(`기본가중치_종합점수`)을 함께 반환 | 얼마나 달라졌는지 투명하게 |

### 10-3. 중요도(1~5) → 가중치

`가중치 = 기본 가중치 × 배수`, 배수는 1:0.4, 2:0.7, **3:1.0(기본)**, 4:1.4, 5:1.8. 곱한 뒤 합 1로 정규화한다. 생략한 관점은 3으로 본다. 배수 값은 연구자가 정한 값이며 실증된 것이 아니다.

### 10-4. 부평역 PC방 예시 (관점 점수 고정: 시장 61.6 / 고객 82.8 / 경쟁 30.2 / 입지 79.8 / 안정 63.9)

| 사용자 설정 | 종합 | 비고 |
|---|---|---|
| 기본(목적방문형) | 64.1 | |
| 안정 우선 (안정성 5, 경쟁성 4) | 61.7 | |
| 경쟁 부담 최소화 (경쟁성 5) | 59.0 | 경쟁성 가중 0.34 |
| 수요 중시 (시장성 5, 고객성 5) | 66.9 | |
| 경쟁성 중요도 1 | 69.3 | 병목 경고 유지 |
| 경쟁성 가중치 직접 0 입력 | 71.5 | 경쟁성 5%로 하한 적용, 병목 경고 유지 |

같은 입지인데 설정에 따라 종합이 59.0~71.5로 움직인다. 경쟁성(30.2)이 병목인 사실은 어느 설정에서도 경고로 남는다.

| 다른 28개 업종 | 변화 없음 | 변화 없음 (커버리지 규칙) |

**주의할 점:** 부평은 인천 9개 상권 중 임대료가 가장 높아 S4가 하위 11%다. 임대료는 번화할수록 높아서, 수요가 큰 상권이 안정성에서 불리해진다. 이중 감점이 될 수 있어, "수요 대비 임대료" 같은 비율 지표로 바꿀지는 팀 결정 사항이다.


### 11-x. 임대료 공정성 점검 (인천 9개 상권 전체)

**상권 좌표 정하는 법(근사).** R-ONE은 상권 경계를 JPG 구획도로만 공개하므로, 상권 이름에 해당하는 역을 중심으로 반경 500m를 상권 영역으로 본다. 이름에 두 지점이 들어간 상권은 두 역 각각의 500m 원을 합친 영역으로 보고, 면적이 두 배가 되는 만큼 수요를 원 1개 기준으로 나눠 맞춘다. (두 역 중간점 하나로 잡으면 역 간 거리가 1~1.7km라 원이 두 역 상권을 모두 놓쳐서 쓰지 않았다.)

**결과**
- 임대료와 수요의 상관은 9곳에서도 약하고 유의하지 않다(점포 ρ=0.55 p=0.13, 활동인구 ρ=0.50 p=0.17).
- 절대 임대료로는 부평이 9곳 중 가장 부담이 크다(S4 11.1). 수요 대비로 보면 두 기준 모두 9곳 중 8위로, 부담이 두 번째로 작다(S4 88.9).
- PC방 점수 비교(13장 코호트 창 적용 전 기준): 절대 방식 안정성 66.2·종합 64.5 / 수요 대비 방식 안정성 77.9·종합 66.6. 채택안은 절대 방식(2026-10-01 팀 결정).
- 중간점 방식으로 계산해도 부평은 8위로 같았다. 즉 결론은 중심점을 어떻게 잡느냐에 크게 좌우되지 않는다.

**판단.** 절대 임대료는 "월세를 감당할 수 있는가"를, 수요 대비 임대료는 "낸 만큼 손님이 있는가"를 본다. 안정성 관점이 '버틸 수 있는가'를 묻는 만큼 두 의미가 다 타당하다. 현재 채택안은 절대 방식이며, 전환 여부는 팀 결정 사항으로 남긴다. 어느 쪽이든 화면에 실제 임대료(35.4천원/㎡)를 함께 보여주는 것을 권장한다.

## 13. 음식 업종 안정성 연결 (mvp-0.3, 2026-10-02)

- 입력: 행안부 인허가 인천 추출본 — 일반음식점 108,872건, 휴게음식점 29,229건 (`engine/etl_stability_food.py`).
- 업종 매핑: 상호 키워드(피자·버거·치킨·토스트·빙수·제과)를 먼저, 나머지는 업태구분명으로. 한 업소는 한 업종에만. 전체의 72.6%(100,326건)가 14개 업종에 매핑됐다. 빵/도넛은 제과점영업 파일이 없어 휴게음식점 '과자점' 업태 + 제과 상호로 근사. 버거는 상호에 버거가 없어도 '패스트푸드' 업태 전체를 포함하므로 다른 패스트푸드가 섞인다(근사). 매핑 규칙은 `etl_stability_food.py` 상단 NAME_RULES·UPTAE_RULES 두 표에만 있다.
- **코호트 창 신설(모든 업종 공통):** 생존율은 2013년 이후 인허가만 쓴다(`etl_stability.COHORT_FROM`). 2000년 이전 폐업 기록이 거의 없어 오래된 코호트가 생존율을 부풀리고, PC방은 2007~08년에 일괄 재등록됐기 때문이다. 폐업률·업력은 전체 기록을 쓴다.
- **기준 분포 필터:** 업종마다 3년 표본 30건 이상인 구만 백분위 기준에 넣는다. 부평구 표본이 30건 미만이면 안정성을 내지 않는다(아이스크림/빙수 24건, 토스트는 기준 구가 5곳 미만).
- 결과: 안정성 산출 업종 1개 → 13개(PC방 + 음식 12개). 다른 네 관점 점수는 29개 업종 모두 변화 없음.
