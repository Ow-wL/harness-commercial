# 인천 상권분석 MVP — 공공데이터 API 조사 결과

> 조사일 2026-09-21 · 대상: 인천광역시 · 용도: 청년 예비창업자 상권 적합도 진단 MVP

---

## 0. 핵심 결론 3줄

1. **경쟁성·고객성·안정성은 전부 구현 가능하다.** 행정동 단위로, 무료로, 인천 커버리지 확인됨.
2. **시장성(유동인구·매출)은 인천에 구조적 공백이 있다.** 서울·경기에 있는 광역 상권분석 인프라가 인천엔 없다. 프록시 설계가 필수.
3. **인천엔 `golmok.seoul.go.kr`(서울)이나 `sbiz.gmr.or.kr`(경기)에 대응하는 서비스가 없다.** 이게 진입장벽이자 곧 이 프로젝트의 기회다.

## 1. ⚠️ 기획서에 즉시 반영해야 할 변경사항 3건

### ① 인천 행정체제 개편 — 2026년 7월 1일 시행 (약 2개월 반 전)

31년 만의 개편이 **이미 시행되었다.**

| 이전 | 이후 |
|---|---|
| 중구(내륙) + 동구 | **제물포구** |
| 중구(영종도) | **영종구** |
| 서구 | **서구 + 검단구** (분리) |

최종 **2군 9구**: 강화군, 옹진군 / 제물포구, 영종구, 미추홀구, 연수구, 남동구, 부평구, 계양구, 서구, 검단구

**설계 영향 (중요):**
- 2026년 6월 이전 기준시점 데이터는 **구 코드(중구·동구·서구)**, 이후는 신 코드를 쓴다. 현재 대부분의 통계가 아직 구 코드다.
- **행정동 코드를 단일 기본 키로 고정하고, 시군구는 파생 속성으로 처리할 것.** 시군구를 조인 키로 쓰면 데이터가 깨진다.
- SGIS 경계 API `year` 파라미터 최대값이 2025라 **개편 미반영 가능성 높음.** 직접 호출로 검증 필요.

> 샘플 지역을 **부평역**으로 잡은 건 운이 좋다. 부평구는 개편 대상이 아니라 코드 불일치 문제를 피해간다. MVP는 부평 그대로 가고, 확장 시점에 개편을 다루는 걸 권장.

### ② LOCALDATA 포털 폐지 → 공공데이터포털로 이관 (2026년 4월 15일 완료)

- 2026-01-25 행안부 발표. 기존 `localdata.go.kr`은 **2026-04-15 병행운영 종료 후 폐지.**
- 총 **209종** 개방 = 인허가 195종 + 생활편의 14종, **전체가 오픈API로 제공.**
- **인허가 195종은 과거 이력 데이터까지 신규 제공** → 시계열(폐업률) 분석 가능.
- 🔴 **인터넷에 돌아다니는 `localdata.go.kr` 기준 예제 코드는 전부 폐기.** `data.go.kr`에서 제공기관 "행정안전부" + 업종명으로 검색해 새 경로를 잡아야 한다.

### ③ 통계청 → 국가데이터처 개편, SGIS 도메인 이전

- `sgis.kostat.go.kr` → **`sgis.mods.go.kr`**
- API: `sgisapi.kostat.go.kr` → **`sgisapi.mods.go.kr`**
- 현재 302 리다이렉트는 동작하나 영구 보장은 불명. 블로그 튜토리얼 대부분이 구 도메인 기준이니 복붙 주의.

> ### 🔴 2026-09-22 실측 정정 — 생활이동의 인천 해상도
>
> 조사 단계에서 공식 문구 *"행정동, 자치구 단위는 수도권(서울, 경기, 인천) 지역만 나오고 나머지 지역은 시·도 단위로 나옵니다"* 를 **"수도권 전체가 행정동 단위"** 로 읽었으나, 실데이터를 받아 확인한 결과 **틀렸다.**
>
> | 지역 | 실제 해상도 | 코드 수 |
> |---|---|---|
> | 서울 | **행정동** | 427개 |
> | 경기 | **시군구** | 47개 |
> | 인천 | **시군구** | 11개 |
>
> 인천·경기 코드는 전부 `...000`으로 끝나는 시군구 코드다. 공식 문구는 "수도권은 행정동 **또는** 자치구 단위"라는 뜻이었고, 인천은 자치구 쪽이다.
>
> **영향:** 인천 시장성은 **시군구 해상도가 한계**다. 경쟁성·고객성(행정동 158개)보다 거칠다. 스코어링에서 시장성 지표에 `fallback: "gugu"`를 기록해 이 사실을 LLM과 사용자에게 노출한다.
>
> **그래도 가치는 남는다:** 시간대별 × 이동목적별 분해는 인천에서 다른 어떤 공공데이터도 제공하지 않는다.
>
> ### ⚠️ 이동목적 중 쇼핑·관광은 사실상 사용 불가
> 인천 11개 구 중 **쇼핑 > 0인 곳이 2개**(연수·미추홀), **관광 > 0인 곳이 1개**(제물포)뿐이다. 9개 구가 0이라 백분위가 무의미하다. → 대체 지표로 **직장성 = 출근유입/(출근유입+귀가유입)** 을 쓴다. 인천 실측 범위 0.194(검단구) ~ 0.365(제물포구).
>
> ### ⚠️ time_cd가 균일하지 않다
> 출퇴근 피크(07~09시, 17~19시)만 **20분 단위**(`0700`,`0720`…`1940`)이고 나머지는 1시간 단위(`00`~`06`,`10`~`16`,`20`~`23`)다. 2자리로만 파싱하면 **피크 6시간이 통째로 누락**된다. 실제로 이 버그로 일평균 유입이 40% 과소집계됐다.

**🔴 인허가 데이터 함정 6개 (모르면 하루 날림):**
1. **인코딩 위장** — HTTP 헤더는 `charset=UTF-8`인데 실제 본문은 **CP949**. 한글 전부 깨짐
2. **좌표계** — **EPSG:5174 추정**(EPSG:2097 이라는 보고도 있음). ⚠️ 두 보고가 충돌하니 **실제 몇 건 뽑아 알려진 좌표와 대조 검증 필수**. 잘못 잡으면 좌표가 태평양으로 감
3. **스키마 변경** — 신 원천은 `도로명전체주소`가 아니라 `도로명주소`. 구 파서 쓰면 주소 전부 null
4. **대용량 정렬** — 전국 통파일이 자치단체코드 순이라 앞부분만 읽으면 인천이 안 나옴. `orgCode`로 지정하거나 스트리밍 파싱
5. **휴업 처리 정책** — 폐업 판정 우선순위는 폐업일자 → 상세영업상태명 → 영업상태명. 휴업 포함 여부로 지표가 꽤 달라짐
6. **인허가 ≠ 실제 개업** — 미개업, 지위승계 재등록이 노이즈. **절대 수치보다 "업종 간 상대 비교"로 포지셔닝할 것**

**임대료는 기대를 낮출 것:** 부동산원은 **표본조사**이고 상권 단위가 행정동보다 훨씬 크다. 상권 구획도가 **JPG 이미지**라 행정동↔상권 자동 매핑이 불가능. MVP에서는 **"군·구 단위 참고치"** 수준으로 낮춰 잡는 게 현실적이다.

### 🔴 기획서 정정 — 예비창업패키지 연령 조건

PDF 기획서에 *"예비창업패키지는 만 29세 이하 생애최초 창업자"* 라고 적혀 있는데 **사실과 다르다.**

2026년 예비창업패키지(중기부 공고 제2026-207호) 실제 조건:
- **연령 제한 없음.** 전 연령 신청 가능
- "만 39세 이하"는 **제외 조건**에만 등장 — *「'19년 이후 수혜 이력이 있고 '최우수' 성과평가를 받은 자로서 공고일 기준 만 39세 이하인 자는 제외」*
- **생애최초 조건 없음**
- 업력: 신청자 명의 사업자등록증 미보유 (기준일 2026.1.22.)

참고로 확인된 다른 사업:
- **청년창업사관학교(창업성공패키지)**: 만 39세 이하 + 창업 3년 이내 (경험창업자 7년 이내)
- **청년전용창업자금(중진공)**: 만 39세 이하 + 사업개시 3년 미만(예비창업자 포함), 연 2.5% 고정

> 아이러니하게도 이 오류 자체가 **프로젝트의 문제의식을 정확히 증명한다.** "기준이 제각각이라 본인 해당 여부 파악 자체가 진입장벽"이라는 PDF의 주장 그대로, 기획자도 틀렸다. 발표 때 이 사례를 쓰면 설득력이 크게 올라간다.

## 4. MVP 데이터 3종 선정안

기획서 요구사항(최소 3종 + 좌표→행정동 변환 + 조인 시연)을 가장 적은 리스크로 만족하는 조합:

| # | 데이터 | 역할 | 조인 키 |
|---|---|---|---|
| 1 | **소진공 상가(상권)정보 CSV** (2026-06-30) | 경쟁성 — 반경 내 동종업종 점포 수 | 좌표 → 행정동 |
| 2 | **행정동 성별·연령별 주민등록 인구** (2026-08-31) | 고객성 — 타겟 연령층 거주 규모 | 행정동 코드 |
| 3 | **수도권 생활이동** (2026-08) | 시장성 — 유입인구 + 쇼핑목적 비중 | 행정동 코드 |
| + | **SGIS 행정구역 경계 GeoJSON** | 좌표→행정동 공간조인 + 지도 렌더링 | — |
| + | **K-Startup 공고 API** | 지원사업 매칭 | 프로필 필터 |

**"조인 시연"이 정확히 이 지점이다:** 1번은 점포 좌표(공간), 2·3번은 행정동 코드(테이블). 경계 GeoJSON으로 point-in-polygon 해서 셋을 하나의 행정동 테이블로 합치는 게 다음주 산출물의 기술적 핵심.

**폐업률(안정성)은 선택:** 인허가 데이터로 가능하지만 함정 6개 때문에 숙련자 기준 1.5~2일이 든다. 1주일 안에 넣으려면 **착수 첫날 인코딩·좌표계·스키마 3개를 먼저 해결**해야 한다. 여유가 없으면 **인천시 소상공인통계의 생존율(1년 80.2% / 3년 55.2% / 5년 40.0%)을 고정 기준선으로 표시**하는 것만으로도 화면은 채워진다.

| 행정동 유동인구 | 생활인구 ✅ | 시군 단위 △ | **없음** |
| 행정동 추정매출 | 상권분석서비스 ✅ | △ | **없음** |

**대응 원칙 3가지:**
1. **절대 매출액을 추정하지 말 것.** 원본이 없으므로 절대값 주장은 근거가 없다. **"인천 내 상대 순위(백분위)"** 로 제시하라. 청년 예비창업자에게도 순위 비교가 더 유용하다.
2. **모든 지표에 출처와 기준시점을 UI에 명시.** 공공누리 1유형 조건(출처표시)이기도 하다.
3. **PDF 기획서의 "Lv.2까지" 원칙과 일관되게** — 수치는 근거와 함께, 판단은 조건부로.

**보완 카드 — 소상공인365 iframe:**
소상공인365(`bigdata.sbiz.or.kr`)는 인천 포함 전국 행정동 단위로 **유동인구·매출·창폐업률·업력을 전부 보유**하고 있다. 다만 오픈API의 실체가 **화면을 iframe으로 임베드하는 방식**이라 원시 수치를 받아올 수 없다.
→ 직접 계산은 불가하지만, **"상세 리포트 보기" 버튼으로 iframe 임베드**하면 우리가 못 만드는 유동인구·매출 화면을 합법·무료로 채울 수 있다. **MVP에서 진지하게 검토할 가치가 있다.** (문의: 소진공 빅데이터실 042-363-7563)
