# 지원사업 자료 조사 (TASKS 13-30, 2026-10-31)

R3 지원사업 연계(앱 v0.3.0 후보)에 쓸 공고 자료를 조사했다. 목표: 분석 위치(인천 구)·업종·사용자 프로필(창업 단계·청년·우대)에 맞는 **지금 신청 가능한 공고**를 카드로 보여 주고, AI 요약·질문이 그 목록 안의 공고만 언급하게 한다(`docs/IMPROVEMENT_PLAN_2026-10-30.md` 6.1장).
조사 방법: 각 기관 공식 페이지를 직접 읽었다(아래 출처). API 실제 응답은 키가 없어 받지 못했다 — 키 없이 호출하면 `{"reqErr":"인증키를 입력해주세요."}` 만 돌아오는 것까지 확인.

## 2. 기업마당 지원사업정보 API (공식 명세, 수정일 2025-10-22)

**요청** `GET https://www.bizinfo.go.kr/uss/rss/bizinfoApi.do`

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `crtfcKey` | Y | 기업마당 발급 인증키 → Cloud Run Secret(`bizinfo-api-key` 예정), 로컬 `.env` |
| `dataType` | N | `rss`(XML) / `json` |
| `searchCnt` | N | 조회 건수. 0 또는 없음 = **전체** |
| `searchLclasId` | N | 분야: 01 금융 · 02 기술 · 03 인력 · 04 수출 · 05 내수 · 06 창업 · 07 경영 · 09 기타 |
| `hashtags` | N | 해시태그(여러 개, 쉼표) — 분야 이름, 지역(`인천` 등 17개 시도) |
| `pageUnit`·`pageIndex` | N | 페이지 크기·번호 |

**응답**(JSON 은 `jsonArray.item[]`, 오류는 `reqErr`). 공고마다 쓸 필드:

| 필드 | 뜻 | 쓰임 |
|---|---|---|
| `pblancId` | 공고 ID(`PBLN_…`) | 캐시 키·중복 제거 |
| `pblancNm` | 공고명 | 카드 제목(원문 그대로) |
| `pblancUrl` | 기업마당 공고 상세 URL | "공고 보기" 링크 |
| `rceptEngnHmpgUrl` | 사업 신청 URL(빈 값 있음) | "신청 페이지" 링크(없으면 공고 URL) |
| `jrsdInsttNm`·`excInsttNm` | 소관기관·수행기관 | 카드 기관명, 인천 기관 판별 보조 |
| `trgetNm` | 지원대상(예: 중소기업) | 대상 배지·매칭(소상공인·예비창업자 등) |
| `reqstBeginEndDe` | 신청기간 `YYYYMMDD ~ YYYYMMDD` | 마감 D-N·지난 공고 제외. **형식 밖 값(상시·예산 소진 시 등) 처리 필요 — 실제 응답으로 확인** |
| `pldirSportRealmLclasCodeNm` | 지원분야 대분류(금융·창업·경영…) | 분야 필터 |
| `hashTags` | 해시태그(연도·분야·지역·기관) | **지역 매칭**(`인천`), 분야 |
| `bsnsSumryCn` | 사업개요(HTML 섞일 수 있음) | 한 줄 요약 — 원문 발췌만(변경 금지), AI 입력엔 제목·기관·대상·마감만 |
| `reqstMthPapersCn`·`refrncNm` | 신청방법·문의처 | 상세 펼침(선택) |
| `creatPnttm` | 등록일시 | 정렬 보조 |

옛 RSS 이름(`title`·`link`·`seq`·`author`·`reqstDt`·`lcategory`)도 같은 값으로 함께 온다. 한도(일 호출 수)는 명세에 없다 — 하루 1회 전체 수집(13-31)이면 문제 없을 것으로 본다.

**키 발급(사용자 작업)**: [기업마당 > 활용정보 > 정책정보 개방 > 지원사업정보 API](https://www.bizinfo.go.kr/apiDetail.do?id=bizinfoApi) 아래 "API 사용 신청" 서식 — 기관(기업)명·신청자명·이메일·전화번호·시스템명·**시스템 URL**(Cloud Run 은 나가는 IP 가 고정이 아니라 IP 대신 운영 주소) 입력, 개인정보 수집 동의 → 키가 화면과 메일로 온다. 문의 02-867-9765. 키 값은 저장소·채팅에 남기지 않고 Secret 에만 넣는다.

## 3. 이용 조건 판단

- 기업마당은 공고를 "누구나 활용"하도록 API 로 개방하고, 같은 출처의 연간 목록을 공공누리 제1유형(출처표시)으로 공개한다. 반면 사이트 저작권 정책은 게재 전 협의·허락과 무단 변경 금지를 요구한다. 두 문서가 다르게 읽히므로 **우리 쪽은 보수적으로 쓴다**:
  1. 공고명·기관·대상·신청기간·링크(사실 정보)만 보이고, 사업개요는 원문 발췌만(요약·고쳐 쓰기 안 함).
  2. 카드에 **"출처: 기업마당(bizinfo.go.kr)"**·기준 시각을 표기하고, 상세는 기업마당 원문으로 연결.
  3. 수익 활동 없음(무료 공개 서비스) — 유료화하면 다시 판단.
  4. AI 는 공고 **제목·기관·대상·마감만** 입력으로 받고, 목록 안 공고명만 언급(13-34 테스트) — 공고 본문을 바꿔 쓰지 않는다.
- 정식 확인이 필요하면 키 신청 때 시스템명·URL 로 용도가 전달되고, 추가로 기업마당(02-867-9765)에 "공고 목록 표시·링크·출처 표기" 범위를 문의할 수 있다(사용자 판단).

## 4. 채택 결정

1. **주 자료 = 기업마당 지원사업정보 API**(`dataType=json`, `searchCnt=0` 전체 또는 `hashtags=인천` + 전국 공고). 하루 1회 수집 → 정규화 → 디스크 캐시, 실패 시 지난 캐시(13-31).
2. **매칭 규칙(13-32 초안)**: 지역 = 해시태그 `인천` 또는 전국 공고(지역 해시태그 없음) · 신청기간 안(마감 지난 것 제외, 상시는 따로 표시) · 대상 = `trgetNm` 에 소상공인·예비창업자·중소기업 등(프로필로 좁힘) · 분야 = 창업·경영·금융 우선. 업종 매칭은 공고에 업종 필드가 없어 제목·해시태그 키워드로만(과장 금지 — "조건에 맞는 공고"이지 "추천"이 아니다).
3. **대안**: 기업마당 키가 막히거나 이용 조건 회신이 부정적이면 K-Startup(제한 없음) + 인천 공고 큐레이션 JSON(10~20건, 수동 갱신, 출처·확인일 표기).
4. **보류**: 소상공인24·인천 기관 게시판 수집 — API 없음. 키 발급 뒤 기업마당에 실제로 얼마나 실리는지 보고 판단.
