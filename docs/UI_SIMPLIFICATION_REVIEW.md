# UI 간소화 — 사용자 요청에 따른 추가 조정

현재 운영 상태(2026-10-19): 사용자 승인으로 `1020200`의 UI와 v0.4를 운영 배포했다. 이하 구현·검증 기록의 커밋 전·운영 미배포 표기는 당시 기록이다. 모바일 결과 지도 시트 참고 주소 한 줄은 production CSS에서 남는 차이가 확인되어 후속 항목으로 등록했다. [배포 기록](DEPLOYMENT_2026-10-19.md).

사용자는 기존 UI를 직접 확인한 뒤 "글이 너무 많고 정보가 과하다. 더 단순하고 세련되게" 바꾸도록 요청했다.
이 요청에 따라 기존 A3의 배치·색·기능을 유지하면서 기본 정보 노출량을 줄였다. 이전 8-C1의 항상 펼친 설명 규칙보다 이 요청을 우선한다.
**현재 상태(2026-10-19)**: 검증 완료 · 커밋 전 · 운영 미배포. Codex 구현·자체 검증 → Claude 브라우저 검토와 mobile 결과 지도 시트 보완 → Codex가 보완 검수 → Claude 로컬 최종 전체 check 9단계 1회 통과(frontend 646건). 아래 "구현 및 검증"은 Codex 실행 이력, "Claude 검토"는 Claude 실행 결과다. 커밋·push·배포는 별도 지시 전까지 하지 않는다.

## 표시 원칙

- 단일 요약: 위치 이름, 종합 점수, 다섯 관점의 막대와 숫자가 중심이다.
- "설명 함께 보기": 헤드라인, 관점별 raw 근거, 가장 높음·낮음 라벨, 충족·가중치·진입장벽, 전체 안내·면책을 펼친다. 다시 접을 수 있다.
- 병목·신뢰도 낮음과 미산출 표시는 간단 화면에도 남긴다. 사용자 가중치 적용 알림도 유지한다.
- 주의 띠: 건수와 최대 두 종류를 먼저 표시하고, 펼치면 기존 요약 원문과 상세 탭 이동 링크를 보여 준다. 5줄 초과의 기존 더 보기 경로도 유지한다.
- 위치 정보: 역·직선거리·참고 주소를 접는다. 비교는 A/B 주소와 두 지점 거리를 하나의 위치 정보로 모은다.
- 비교 요약: 두 위치의 점수와 다섯 관점 그래프 중심. 계산 구성 차이는 주의 제목에 남기고, 자세한 해석은 설명 펼침과 상세 근거에서 확인한다.
- 기본 면책은 짧게 남긴다. 정확한 점수 해석은 "이 점수는?", 전체 안내는 설명 펼침, 엔진 원문은 상세 근거에 보존한다.
- 분석 전 긴 소개를 한 문장으로 줄이고, 반경 영향 설명은 펼침으로 바꾼다. 좌표·주소 입력과 반경 변경 로직은 그대로다.

## 구현 및 검증

`ResultQuiet.css`는 위 표시 정책과 여백·타이포그래피를 담당한다. 분석·비교·캐시·복구 상태 기계는 수정하지 않았다.
기존 경고 링크 검증은 주의 요약을 먼저 펼친 후 같은 원문·링크·포커스를 검사하도록 바꿨다. 기존 단언을 삭제하지 않았다.
추가 6건은 실제 CSS 파일을 주입하여 기본 가시성, 설명 펼침·접힘, 주의 펼침·포커스, 주소 펼침, 경고 유지, 비교 간소화를 확인한다.

브라우저: 로컬 개발 서버의 v0.4 실제 응답과 실제 GPU 다크 지도에서 1024×800 및 375×812 단일·비교를 확인했다.
375px에서 가로 넘침 없이 다섯 관점이 고정 하단 버튼 위에 들어왔다. PC방뿐 아니라 네일숍의 병목·미산출·신뢰도 낮음도 확인했다. 미산출 숫자 칸 폭과 모바일 행 간격을 조정해 해당 표시가 하단 버튼에 가리지 않게 했다. 비교 중 500m→1km 전환, 주의 링크→상세 탭·포커스 이동, 실제 A/B 참고 주소 구분도 확인했다.
캡처는 git 제외 `.gstack/browse-reports/quiet-ui/`에 있다. 실제 모바일·Safari·Firefox·스크린리더는 확인하지 않았다.
샌드박스의 최초 프런트 실행은 임시 파일 ENOENT로 23개 suite가 시작되지 못했고, 일반 로컬 실행으로 전환했다. 이후 프런트 639건 중 5건은 주의 요약의 접근 역할 변경 때문에 실패했고, region 컨테이너 복구와 펼침 동작 반영 후 관련 51건이 통과했다. 새 가시성 테스트는 CSS import가 비워지는 테스트 환경에 맞춰 실제 스타일 파일을 읽도록 고친 뒤 6건이 통과했다. 타입 검사와 lint도 통과했다.

전체 check 1회차는 앞의 8단계가 통과하고 frontend에서 주소 테스트 4건이 실패했다(645건 중 641건 통과). 주소를 예전 카드 안에서 찾던 단언을 새 A/B 위치 정보 영역으로 옮겼고, 서로 다른 쪽 주소가 섞이지 않음·좌표별 조회 횟수·늦은 응답·인증 실패 처리 검증은 유지했다. 수정 후 주소 테스트 묶음 6건 통과, production build 통과. 이후 실제 네일숍 모바일 확인으로 행 간격 CSS를 보완했다. 전체 check 2회차의 프런트 단계 전에 제품 코드를 확정했다.
