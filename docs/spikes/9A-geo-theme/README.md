## s1 행정동 union → 구 경계·외곽선 (결과)

| 항목 | 결과 |
|---|---|
| union 모양 | 경계는 **해안선·섬 윤곽**을 따른다(넓은 해역을 포함하지 않는다). 본토·영종·강화·옹진 섬까지 외곽선 조각 110개, 구 경계 조각 117개(옹진군 77·강화군 17·영종구 15). 면적 합 약 1,174 km²(위도 근사) |
| 구멍 | union 결과에 면적 0 m² 구멍(남동구 2·외곽 3, 부동소수 잡음) → 제거 규칙 필요(20,000 m² 미만 구멍, 2,000 m² 미만 조각 제거) |
| 크기 | 원본 좌표 그대로: 구 330KB·외곽 275KB. 표시용 단순화(구 1e-4°≈10 m, 외곽 2e-4°≈20 m, 소수 5자리): **구 97KB · 외곽 66KB**(gzip 시 각 약 60KB·50KB — 운영 FastAPI는 gzip 미적용, `backend/app/frontend.py`) |
| 그리기 비용 | `naver.maps.Polygon` 229개(구 117 + 외곽 110 + 핀·원): GL 다크 468~472 ms, 래스터 103 ms(1회, 재생성 때마다). 줌 전환은 `setOptions`만이라 즉시 |
| `naver.maps.Data` | `addGeoJson`은 예외 없이 feature 배열을 돌려줬으나 검수 코드의 메서드 이름 오류(`getGeometry`)로 타입은 확인 못 함. 지금 제품이 쓰는 `Polygon` 방식으로 충분하므로 Data 레이어는 쓰지 않는다 |
| 위계 | 외곽 2px 실선 › 구 1px 실선 › 행정동 1.5px 점선(제품) — 캡처 `03`·`04`에서 구분됨. 해안에서는 외곽선이 구 경계 위에 겹쳐 그려진다(의도) |
| 밖 영역 dim | 세계 사각형 + 외곽 조각 110개를 구멍으로 한 Polygon 1개(캡처 `05`). 다크에서 `rgba(10,18,38,.45)`는 바깥이 조금 어두워지는 정도라 **효과가 약하다**; 밝은 지도에서는 §2.6 토큰(0.06) 수준이면 거의 보이지 않는다. 범위 안내로는 외곽선이 더 분명하다 |

→ 구현: `scripts/build_geo.py`에 union·정리·단순화 규칙을 넣고 **파일 1개**(`인천_시군구경계_2026.geojson`: 구 11 feature + 외곽선 1 feature, 속성에 라벨 기준점)로 매니페스트에 추가. 프런트는 `dongBoundary.ts`와 같은 `?url` 방식으로 첫 지도 표시 때 1회 받는다. 옹진군 섬 조각은 ≤11에서만 의미가 있으므로 줌 ≥12에서는 외곽선 조각 중 화면 밖 것을 그리지 않는 최적화는 **불필요**(총 1회 470 ms, 이후 비용 없음).

## s2 라벨 겹침·지명 색 (결과)

- **밝은 래스터 지도(대체 지도)**: NAVER 자체 구 라벨이 이미 선명하다. 자체 라벨을 더하면 **같은 이름이 두 번**(캡처 `03` "남동구남동구", `01` 부평구·미추홀구). 래스터 라벨은 SDK로 끌 수 없다.
- **다크 GL 스타일**: NAVER 구 라벨은 §19.4 색(`#A7B3CA`/`#8593AE`)이라 흐리고, 자체 라벨 L1(`#C7D1E4` + 진한 halo)은 선명하다(캡처 `04`). 그러나 여기서도 NAVER 라벨과 **이중 표시**가 된다(미추홀구).
- 줌 10 이하에서는 구 11개 라벨이 서로 겹친다(캡처 `05`: 검단·서해·계양·부평·제물포·미추홀·남동·연수가 한 덩어리). 자체 라벨을 쓴다면 ≤10은 숨기거나 "인천" 하나만.
- **결론·권고**: 라벨은 **한 출처만** 쓴다. 자체 라벨을 그리면 래스터 지도에서 중복을 피할 수 없으므로, **NAVER 라벨을 쓰고 다크 스타일의 지명 색만 밝게 재발행**한다(시·구 지명 목표 L1 수준 `#C7D1E4`~`#EEF2FA` + halo, 동 지명 한 단계 밝게). 코드에는 경계선만 추가한다. 재발행은 사용자 작업(Style Editor)이고, 글자 크기 조정 가능 여부는 편집기에서 확인한다. 자체 라벨은 Style Editor에서 지명을 끌 수 있을 때만 대안으로 남긴다.

## s3 테마 전환 = 지도 재생성 (결과)

| 전환 | init까지 | 오버레이 재그리기 | 상태 유지 |
|---|---|---|---|
| 밝은 래스터 → 다크 GL(스타일) | **1,206 ms**(파기 포함 1,240 ms) | +468 ms | 중심·줌(래스터 13 → GL 12 환산) 유지, 핀·원·경계·라벨 재그려짐 |
| 다크 GL → 밝은 래스터 | **17 ms**(파기 포함 21 ms) | +103 ms | 동일 |
| 첫 로드 다크 GL | 3,800 ms(1회), 다른 1회는 **8초 init 시간 초과 → 밝은 지도 복구**(그리는 동안이 아니었던 것으로 보임 — 제품 §19.3.1의 "보이는 동안만 세기" 규칙이 필요한 이유 재확인) | | |

→ 구현: 테마 전환은 제품 `MapView`의 세대 번호·복구 경로를 그대로 재사용해 지도를 다시 만든다. 밝은 테마의 지도는 (a) 래스터 기본 지도(즉시) 또는 (b) GL 라이트 스타일(약 1.2초, 사용자 발행 필요) — 사용자 결정(계획 §6 Q2). 전환 중 약 1초는 로딩 표시(지도 영역만, 패널은 즉시 전환).
