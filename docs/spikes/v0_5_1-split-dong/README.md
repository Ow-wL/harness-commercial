# v0.5.1 분동 배분 결함 수정 — 재현·가정·차이 (2026-10-24, D-029)

Codex 검수 지적: 팀 엔진 v0.5 `etl_boundary.DongAreas`가 이미 분동된 패널 값에 분동 인구비를 다시 곱한다.

## 1. 원인 (팀 엔진 유래)
- 신설 분동(아라1·2동, 운서1·2동)은 SGIS 2025 2Q 경계에 없어 모체 경계(아라동·운서동)로 연결된다. 이때 가중치 `w = |원∩모체|/|모체| × ratio`, `ratio = 분동 총인구 ÷ 형제 분동 총인구 합`.
- 그런데 `radius_profile`이 곱하는 패널 값(총인구·종사자수·타겟_업종)은 이미 분동별 값이다 → 배분 인구 = 면적 비율 × ratio × 분동 값. 인구비가 두 번 들어가 모체 총량보다 작아진다(아라동 약 51%).
- 이 비율은 팀 `etl_sgis.attach`에서 온 규칙이다. 거기서는 SGIS **모체 동 통계**(종사자·1인가구 등)를 분동에 나누므로 맞다. `etl_boundary`는 분동 값에 다시 적용해 이중이 됐다.

## 2. 재현 테스트
`tests/split_dong_case.py` — 4km 정사각형 모체 경계 1개, 같은 총량의 패널 두 벌(분동 전 아라동 1행 / 분동 후 아라1·2동 2행). 거주·종사자·타겟·잠재수요 모두 확인.
- v0.5(`tests/engine_v0_5`): 분동 후 = 분동 전 × Σ(ratio·x)/Σx — 보존되지 않음을 고정(약 절반). v0.5는 팀 결과(golden) 보존용이라 결함을 그대로 둔다.
- v0.5.1(`tests/engine_v0_5_1`): 합성 사례 세 반경 보존 + 실데이터(분동을 모체 1행으로 합친 패널과 4개 분동 중심점·세 반경에서 같은 값).

## 3. 배분 가정 확인 — 왜 "비율 1.0"인가
| 가정 | 내용 | 아라1동 중심점 500m 거주 | 운서2동 중심점 1km 거주 |
|---|---|---|---|
| 팀 v0.5(결함) | 모체 면적 비율 × 인구비 × 분동 값 | 8,288 | 1,249 |
| **v0.5.1: 모체 균등** | 분동들이 모체 경계 안에 고르게 산다 → 모체 면적 비율 × 분동 값. 분동 전후 총량 보존 | 16,119 | 2,443 |
| 대안: 2026 자식 경계 | 분동마다 2026 경계(`인천_행정동경계_2026.geojson`)로 따로 면적 비율(shapely 근사) | 약 15,500 | 약 7,300 |

- 아라동은 두 가정의 차이가 ±3% 정도다. 운서동은 모체에 공항·해역이 넓어 두 가정 모두 거칠고 차이가 크다.
- v0.5.1은 엔진의 기존 가정(동 안 균등 거주, 경계 출처 SGIS 2025 하나)을 그대로 따르는 "모체 균등"을 택했다. 2026 자식 경계를 쓰면 경계 출처가 섞이고(2026 경계는 해안 범위도 다름) 설계 변경이라 다음 과제로 둔다.
