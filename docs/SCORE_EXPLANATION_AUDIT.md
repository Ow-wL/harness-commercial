## 1. 실제 웹 분석 경로의 반경 잠재수요 공식

### 현재 설명
- [상세] 3-3: "잠재수요 = 유입인구 × 0.3 + 거주인구 × 0.7. 반경이 여러 행정동에 걸치면 점포 분포로 면적가중한다."
- [설계] 3장 경쟁성: `잠재수요 = 유입인구 × 0.3 + 거주인구 × 0.7`, `P2 = 잠재수요 / 동종점포수`
- [상세] 4장 2번: 연구자가 정한 파라미터 목록에 "잠재수요의 0.3:0.7 비율"

### 실제 계산
웹(`POST /analyze`)과 golden 모두 `AnalysisService.analyze`가 `radius_profile`을 넘기므로 `score_competition`은 **반경 프로파일 경로**를 탄다.

```
w_d       = min(1, 반경 500m 안의 행정동 d 점포 수 / 행정동 d 전체 점포 수)     ← 점포 분포 기반 배분 비율
반경수요   = Σ_d  w_d × 총인구_d                                               ← 패널_통합.csv 주민등록 총인구(전 연령)
P2 원시값  = 반경수요 / 반경 안 같은 업종 점포 수                                ← "점포당 잠재수요"
```

- **유입(유동)인구는 들어가지 않는다.** 가중치 0.3/0.7도 쓰지 않는다. 인구는 타겟 연령이 아닌 전체 주민등록 인구다.
- `유입×0.3 + 거주×0.7` 식은 `radius_profile`이 없을 때(점포 리스트를 직접 넘기는 `demo.py` 합성 데이터 경로)에만 실행된다. 웹·golden은 이 분기를 타지 않는다.
- 검증 (부평역 37.4894, 126.7246 · PC방): 반경 내 전체 3,232곳, PC방 12곳. 걸친 행정동 4곳 — 부평5동 w=0.542 → 17,894명, 부평1동 w=0.517 → 17,787명, 부평6동 w=0.807 → 15,460명, 부평2동 w=0.123 → 2,057명. 합계 53,198명 ÷ 12 = **4,433명** (golden `반경_추정수요`·`점포당_잠재수요`와 같음).
- 비교 모집단: 158개 행정동 **점포 중심점**을 가상 분석 지점으로 놓고 같은 식을 돌린 값 중 **반경 안 같은 업종이 1곳 이상인 지점만** 쓴다. N은 업종마다 다르다 (PC방 96, 카페 142, 편의점 141, 요가/필라테스 120). PC방 중앙값 6,955명. P1(동종업종 비중, 역방향)은 158개 중심점 전부를 쓴다 (값이 없으면 0).

### 코드 위치
- `scoring_engine/service.py:61` `radius_demand.radius_profile(...)` 호출, `:95` P2 비교 모집단 필터(`반경_동종점포 > 0`), `:71` P1 비교 모집단
- `scoring_engine/v0_3/radius_demand.py:33-60` `radius_profile` (`:45-51` 배분 가중·반경수요), `:63-75` `build_reference`
- `scoring_engine/v0_3/scoring.py:309-313` 실제 경로, `:314-323` `유입×0.3+거주×0.7` (합성 데이터 경로), `:346-353` P2·P1 백분위
- `scoring_engine/reference.py:35-41` 경쟁성 비교 모집단 캐시

### 수정 문구
> **점포당 잠재수요** = 반경 500m 추정 거주인구 ÷ 반경 안 같은 업종 점포 수.
> 추정 거주인구는 반경에 걸친 행정동마다 "반경 안 점포 수 ÷ 그 동 전체 점포 수"(최대 1)만큼 그 동의 주민등록 총인구를 나눠 더한 값입니다. 유입(유동)인구는 쓰지 않습니다.
> 비교 대상은 인천 158개 행정동의 점포 중심점에서 같은 방식으로 계산한 값 중, 반경 안에 같은 업종이 있는 지점입니다.

[상세] 4장의 "잠재수요의 0.3:0.7 비율"은 실제 점수에 영향이 없으므로 연구자 파라미터 목록에서 빼야 한다 (원본 수정 불가 → 다음 판 문서에서 반영).

### 한계
- 유동·직장 인구가 빠져 있어 역세권·오피스 상권에서 수요를 낮게 잡을 수 있다 (카페·백반처럼 직장인 수요 업종에 불리할 수 있음). 반영하려면 엔진 버전 변경이 필요하다.

## 2. 시간대 적합도 1.0의 실제 기준

### 현재 설명
- [엔진] `scoring.py:58` 주석: "1.0 = 인천 평균 수준, >1.0 = 내 영업시간에 사람이 몰림, <1.0 = 엇갈림."
- [상세] 3-1: "1.0이 인천 평균이다." / [설계] 3장: "1.0 = 인천 평균"
- [시안] 그림 설명: "1.00이 인천 평균이므로, 영업시간대에 사람이 평균보다 32% 더 몰린다."

### 실제 계산
```
time_fit = 24 × Σ_h ( w_h × p_h )
  w_h = 업종 영업시간 가중 HOUR_PROFILE (합 1로 정규화)
  p_h = 분석 지점이 속한 시군구의 시간대별 유입 비중 (패널_시장성_202608.csv h00~h23, 합 1로 정규화)
```
- **1.0은 업종 영업시간 또는 지역 유입 중 하나가 24시간 균등할 때 나오는 값**이다. 인천 평균과 관계없다. 확인: 균등 업종 × 아무 구 = 1.000, PC방 × 균등 유입 = 1.000.
- 대부분 업종은 낮·저녁에 영업하고 유입도 낮에 몰리므로 거의 모든 구에서 1.0보다 크다. 인천 11개 구 유입을 합친 분포로 계산하면 업종별로 **0.89(일반 유흥 주점) ~ 1.51(입시·교과학원)**이다.
- PC방: 인천 합산 기준 1.287, 11개 구 중앙값 1.277, 부평구 1.32. 즉 부평구 PC방은 인천 합산보다 **약 3% 높을 뿐**이며 "평균보다 32% 더 몰린다"는 틀렸다.
- 점수(M3)는 이 값을 인천 11개 구의 같은 계산과 비교한 백분위다 (부평구 PC방 63.6 = 11개 구 중 7개 구보다 높음). **점수 자체는 1.0 해석과 무관하게 맞다.** 틀린 것은 원시값 1.0의 해석이다.
- 영향: flag 기준(`> 1.20` 집중, `< 0.85` 엇갈림)도 균등 기준이다. 29개 업종 × 11개 구 = 319개 조합 중 271개(85%)에 `영업시간대_유입_집중`이 붙고, 21개 업종은 11개 구 전부에서 붙는다 (golden PC방에도 붙어 있음). 이 flag는 "인천 다른 곳보다 몰린다"는 뜻이 아니다.

### 코드 위치
- `scoring_engine/v0_3/scoring.py:55-67` `time_fit`, `:151` 업종 프로파일, `:157-158` M3 값·비교 모집단, `:190-193` flag
- `scoring_engine/v0_3/config.py:229` `HOUR_PROFILE` (추정치라고 주석에 명시)
- `scoring_engine/runtime.py:84` 비교 모집단 `inflow_by_hour` (11개 시군구)

### 수정 문구
> **시간대 적합도** = 이 업종의 영업시간 가중과 이 구의 시간대별 유입 비중이 얼마나 겹치는지를 나타낸 값(×24)입니다.
> 1.0은 "시간대 구분이 없을 때(24시간 균등)"의 값이며 인천 평균이 아닙니다. 대부분 업종은 사람이 많은 낮·저녁에 영업하므로 인천 대부분 구에서 1.0보다 큽니다(인천 전체 기준 PC방 약 1.29).
> 점수는 이 값을 인천 11개 구의 같은 계산과 비교한 백분위입니다(높을수록 좋음).

### 한계
- `HOUR_PROFILE`은 연구자 추정치다 (실제 업종별 매출 시간 분포 아님).
- 유입은 시군구 단위, 도착 기준 인원이며 체류 시간이 아니다.
- flag 기준·엔진 주석은 v0.3 변경 금지 영역이라 고칠 수 없다. 화면에 flag 이름이 원문으로 보이므로(`IndicatorDetails` flags 칩) 별도 표시 규칙이 필요하다 (7장).

## 3. 세부지표 백분위와 관점·종합 가중평균 점수의 차이

### 현재 설명
- [웹] 종합 점수 아래 "인천 158개 행정동 대비 백분위" (`OverallScore.tsx`, `DESIGN.md` §6·§8.1) — **이번에 수정**
- [시안] 종합 점수 아래 같은 문구
- [엔진] `meta.정규화_기준` = "인천 전체 행정동 백분위" (화면 "데이터 출처" 줄에 그대로 표시)
- [엔진] 병목 경고 "{관점}이(가) 인천 하위 {점수}%로 …" — 관점 점수를 백분위처럼 읽는다
- [웹] 5대 관점 막대 범례 "50 = 인천 중앙"
- [상세] 1장 "80점 = 비교집단의 80%보다 높다는 뜻" (세부지표에만 맞는 설명)

### 실제 계산
1. **세부지표 점수 = 백분위.** 비교 모집단(None·비유한값 제외, 5개 미만이면 None)에 대해
   - **정방향**(높을수록 좋음): `p = (값이 엄격히 작은 개수) ÷ N × 100`
   - **역방향**(낮을수록 좋음 — P1 동종업종 비중, L1 최근접역 거리, S2 폐업률, S4 임대료): `100 − p` = (값이 **같거나 큰** 개수) ÷ N × 100
   - **동점:** 정방향은 같은 값(자기 자신 포함)을 "낮은 곳"으로 세지 않아 동점이 불리하게, 역방향은 같은 값을 "같거나 큰 곳"에 넣어 동점이 유리하게 들어간다. 예: 모집단 [1, 2, 2, 3, 4]에서 값 2 → 정방향 20, 역방향 80 (`pct_rank` 직접 실행으로 확인).
   - **정방향 최댓값:** 분석 지점 자신이 모집단에 들어 있으면(시장성·고객성·안정성) 자기 값이 "작은 값"으로 세지지 않아 최대 `(N−1)/N × 100` — 시장성 90.9, 고객성 99.4, 안정성(PC방, N=9) 88.9. 모집단이 점포 중심점이라 분석 지점이 들어 있지 않은 경쟁성·입지성은 정방향도 100이 나온다 (golden: L2 29개 업종 100.0, P2 1개 업종 100.0).
   - **역방향 최댓값:** 모집단 최솟값과 같거나 더 작으면 자기 포함 여부와 관계없이 **100**이다 (golden: S2 폐업률 2개 업종 100.0, L1 99.4는 중심점 1곳이 더 가까운 경우). 자기 자신이 모집단에 있으면 역방향 최저점은 0이 아니라 `100/N`이다.
   - **예외 2개 (엄밀히는 백분위가 아님):** C4(1인 세대 비중)는 정방향 백분위를 `50 + (백분위 − 50) × 업종 민감도`로 50 쪽으로 줄인 값이라 범위가 `50 ± 50 × 민감도`다 (PC방 민감도 0.6 → 약 20~80). L3(유인시설 근접도)는 업종의 유인시설 종류별 정방향 백분위의 평균이다 (종류별 값이 모두 없으면 합계의 백분위).
2. **관점 점수 = 세부지표 점수의 가중평균.** 계산된 세부지표만으로 가중치를 다시 합 1로 맞춘다. 계산된 가중치 비율(coverage)이 0.5 미만이면 None.
3. **종합 점수 = 관점 점수의 가중평균.** 업종그룹 가중치(또는 사용자 가중치)로, 계산된 관점만 다시 정규화한다.

→ 관점·종합 점수는 **백분위들의 평균**이라 그 자체로는 백분위가 아니다. 평균을 거치면 값이 가운데로 모인다.
- 확인 (PC방, 웹 경로): 인천 158개 행정동 점포 중심점 중 분석 가능한 144곳(7곳 `location_outside`, 7곳 `no_data_nearby`)의 종합 점수는 최소 14.1, 10%점 36.6, 중앙 51.5, 90%점 63.3, 최대 71.9.
- 같은 웹 경로로 계산한 부평역 PC방 종합 65.8은 이 144곳의 96.5%보다 높다. 점수 65.8을 그대로 백분위로 읽으면 이 분포와 크게 어긋난다.
- 위 분포는 오해를 보여 주기 위한 예시일 뿐 검증된 기준 분포가 아니다. 엔진에는 종합 점수의 비교 분포가 없으므로 **종합에서 "상위 N%"를 계산하거나 표시하지 않는다.**

### 입증하는 것
- 부평역 한 지점에서, 관점 점수가 주어졌을 때, 관점 가중치를 ±20~50% 무작위로 바꾸거나 동일 가중으로 바꿔도 **29개 업종의 순위가 대체로 유지된다.**

### 입증하지 못하는 것
1. **가중치가 옳다는 것.** 성공·폐업 결과 데이터와 비교한 검증이 아니다 (타당성 ≠ 안정성).
2. **관점 점수를 만드는 규칙.** 세부지표 가중치(M1 0.40 등), `pct_rank` 규칙, `HOUR_PROFILE`·`WORK_PREF`·`AGE_PROFILE`·`ANCHOR`·`SOLO_SENSITIVITY`, 반경 500m, 감쇠 거리 400·300m, `MIN_COVERAGE`, 병목 기준 25 — 모두 고정했다.
3. **다른 지점.** 부평역만 분석했다.
4. **웹의 주 사용 방식.** 웹은 "업종 하나를 정하고 위치를 고르는" 흐름이라 위치 간 비교가 중요하지만, 분석은 한 위치의 업종 순위만 봤다. 한 지점 **종합 점수 값 자체가 얼마나 움직이는지**도 측정하지 않았다.
5. **웹 경로의 결과.** 입력이 임대료를 포함한 golden 관점 점수다. 웹(임대료 제외, 5장)으로는 다시 계산하지 않았다.
6. **사용자 가중치 규칙.** 관점당 최소 5%(`MIN_WEIGHT`) 하한과 중요도 배수(`IMPORTANCE_MULT`)는 이 시뮬레이션에 들어 있지 않다.
7. **경쟁성 정의의 타당성.** 업종 순위는 경쟁성에 크게 좌우되는데(제외 시 0.47), 경쟁성의 핵심인 점포당 잠재수요 정의(1장: 거주인구만, 점포 분포 배분)는 검증하지 않았다.

### 코드 위치
- `sources/team_v0.3/04_엔진코드/sensitivity.py:13-18` `comp`(관점 점수 고정 가중평균), `:24-43` 무작위 가중치·지표, `:44-47` 동일 가중, `:48-54` 관점 제외
- 가중치 정의: `scoring_engine/v0_3/config.py:154` `WEIGHTS`

### 수정 문구
> 가중치 민감도 분석은 부평역 한 지점에서, 관점 점수를 고정한 채 관점 가중치만 ±20%·±50% 흔들었을 때 29개 업종 순위가 대체로 유지됨(순위 상관 0.98·0.93)을 보였습니다. 가중치가 옳다는 증거는 아니며, 세부지표 계산 규칙·업종 파라미터·다른 지점·위치 간 비교·웹(임대료 제외) 결과는 검증 범위 밖입니다. 업종 순위는 경쟁성 지표에 크게 좌우됩니다(경쟁성 제외 시 순위 상관 0.47).
