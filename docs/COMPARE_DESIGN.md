### 1.1 같은 구·동에서 점수가 같아지는 이유 (엔진 실측)

관점마다 분석 지점 값의 공간 단위가 다르다(`SCORE_EXPLANATION_AUDIT.md` 4장 표).

| 관점 | 분석 지점 값의 단위 | 같은 구 두 위치 | 같은 동 두 위치 |
|---|---|---|---|
| 시장성 | 시군구 | **같다** | **같다** |
| 고객성 | 행정동(좌표가 든 polygon) | 다를 수 있다 | **같다** |
| 경쟁성 | 지점 반경 500m | 다를 수 있다 | 다를 수 있다 |
| 입지성 | 지점 좌표(최근접역·역세권·유인시설) | 다를 수 있다 | 다를 수 있다 |
| 안정성 | 시군구 × 업종 | **같다** (둘 다 산출된 경우) | **같다** |

2026-10-11 `.venv` 엔진(`AnalysisService` + `ContextBuilder`)으로 확인한 값:

| 업종 · 쌍 | 종합 | 시장성 | 고객성 | 경쟁성 | 입지성 | 안정성 |
|---|---|---|---|---|---|---|
| 카페 · 같은 동 (부평1동 37.4894,126.7246 / 37.4920,126.7230) | 62.9 / 60.7 | 44.4 / 44.4 | 81.3 / 81.3 | 48.0 / 37.2 | 93.4 / 92.0 | 55.1 / 55.1 |
| 카페 · 같은 구 다른 동 (부평1동 / 산곡2동 37.5035,126.7040) | 62.9 / 55.7 | 44.4 / 44.4 | 81.3 / 52.7 | 48.0 / 75.6 | 93.4 / 56.2 | 55.1 / 55.1 |
| PC방 · 다른 구 (부평1동 / 구월3동 37.4475,126.7015) | 65.8 / 59.1 | 61.6 / 68.7 | 82.8 / 91.4 | 30.2 / 24.4 | 79.8 / 79.5 | 73.2 / 24.8 |

- 같은 구 안의 비교에서는 시장성·안정성 차이가 구조적으로 0이다. 같은 동이면 고객성도 0이다. 이 경우 위치 차이는 경쟁성·입지성에만 나타난다.
- 점수가 같다는 사실로 "같은 단위라서"라고 판단하지 않는다. 우연히 같을 수도 있기 때문이다. 안내는 **context의 `gu_code`·`dong_name` 비교**로만 띄운다(5.3).
- 모집단이 작은 지표(시장성 11개 구, 안정성 6~11개 구)는 점수가 9~17점 단위로 끊긴다. 그래서 다른 구끼리 비교하면 작은 실제 차이가 큰 점수 차이로 보일 수 있다(5.2 안내 문구).

## 2. 사용자 흐름

```
[A 결과 화면]  conditions-summary: [지도 보기(mobile)] [다른 위치와 비교] [조건 변경]
      │ "다른 위치와 비교"
      ▼
[B 고르기]  패널: A 요약 카드(위치·업종·종합) + "B 위치" 카드(지도 클릭 또는 좌표 입력) + [B 분석하기] [비교 취소]
            지도: A 마커(고정) + 지도 클릭 = B 선택. 업종은 A와 같음(바꿀 수 없음, 표시만)
      │ "B 분석하기" → POST /analyze {B 좌표, A 업종}
      ▼
[B 분석 중]  B 카드에 "B 위치 분석 중…"(aria-live). A 요약은 그대로. 지도 클릭 무시
      │ 성공                         │ 실패
      ▼                              ▼
[비교 결과]                      [B 오류] B 카드 안 ErrorBlock(role=alert). A는 그대로
  표·안내·경고·동종 점포           [다시 시도] [B 위치 다시 고르기] [비교 취소]
  [B 위치 다시 고르기] [비교 종료]
      │ "비교 종료" / "비교 취소"
      ▼
[A 결과 화면] (A 결과·A 동종 점포 목록 그대로 복원)
```

- A는 비교하는 동안 **고정**한다. A를 바꾸려면 비교를 끝내고 "조건 변경"을 쓴다(12장 D1).
- "조건 변경"은 비교 중에도 보인다. 누르면 비교를 끝내고 지금과 같이 조건 화면으로 돌아간다. A의 위치·업종 선택값은 지금처럼 남는다.

## 3. 상태 모델

A는 기존 `analysis`를 그대로 쓰고, 비교는 별도 상태 하나로 둔다. A의 `inflight`·`seq`는 건드리지 않는다.

```ts
/** B 분석 상태. A(analysis)가 success일 때만 off가 아니다 */
type Compare =
  | { status: 'off' }
  | { status: 'picking'; location: LatLng | null }
  | { status: 'loading'; location: LatLng; request: AnalyzeRequest }
  | { status: 'error'; location: LatLng; request: AnalyzeRequest; failure: ApiFailure }
  | { status: 'success'; location: LatLng; request: AnalyzeRequest; response: AnalyzeResponse }

// B 요청 전용: compareInflight {seq, controller}, compareSeq
// B 동종 점포: nearbyB: NearbyState | null (+ 전용 inflight/seq)
// 화면에 보이는 동종 점포 기준: storeSide: 'A' | 'B'
```

- B 요청 body = `{ lat: B.lat, lng: B.lng, biz_code: A.request.biz_code }`. 업종은 A 요청에서만 가져온다.
- B 응답을 받아들이는 조건(모두 참이어야 한다):
  1. `compareInflight.current?.seq === current.seq` (늦은 응답·취소된 요청 폐기)
  2. `matchesRequest(response, request)` (기존 함수 재사용: 좌표·업종코드)
  3. `response.result.meta.업종코드 === A.response.result.meta.업종코드`
  - 2·3이 거짓이면 기존과 같이 `schema` 실패로 다룬다(`console.error` + 계약 오류 화면).

### 3.1 상태 전이

| 사건 | 이전 상태 | 다음 상태 · 부수 효과 |
|---|---|---|
| "다른 위치와 비교" | A success, compare off | `picking(null)`. A 점포 선택(`activeStoreId`)을 지운다. A 동종 점포 데이터는 지우지 않는다. mobile은 지도 화면으로 |
| 지도 클릭·좌표 입력 | picking | `picking(점)` |
| 〃 | error / success | `picking(점)`. B 결과·B 오류·B 동종 점포를 지운다(새 위치와 이전 B 결과가 섞이지 않게) |
| 〃 | loading | 무시한다(현행 §8.12 "분석 중 새 클릭 무시"와 같다) |
| "B 분석하기" | picking(점) | `loading`. 이전 B 요청은 abort. 점이 A 좌표와 같으면 요청하지 않고 B 카드에 "A와 같은 위치입니다. 다른 위치를 고르세요." |
| B 응답 성공 | loading | `success`. B 동종 점포를 조회한다(실패해도 비교 결과는 그대로). `storeSide = 'B'`. 포커스는 `#compare-title`. mobile은 패널 화면으로 |
| B 응답 실패 | loading | `error(failure)`. A·A 동종 점포는 그대로 |
| "다시 시도" | error | 같은 `request`로 `loading` |
| "B 위치 다시 고르기" | error / success | `picking(null)`. B 상태 전부 지움. mobile은 지도 화면으로 |
| "비교 취소"·"비교 종료" | off가 아닌 모든 상태 | `off`. B 요청·B 동종 점포 요청 abort, B 상태 지움, `storeSide = 'A'`, 점포 선택 지움. 지도 선택 지점은 A로 돌아가 `panTo(A)`(zoom 유지). 포커스는 "다른 위치와 비교" 버튼으로 |
| "조건 변경" | 비교 중 어느 상태든 | 비교 종료와 같은 정리 후 기존 `cancelAnalysis()`(A도 지움) |
| 업종 변경 | — | 비교 화면에는 업종 선택이 없다. 업종을 바꾸는 유일한 길은 "조건 변경"이고, 그때 비교는 끝난다. B만 다른 업종으로 분석하는 경로는 만들지 않는다 |
| 새 A 분석 시작(`runAnalysis`) | — | 시작 전에 비교를 `off`로 정리한다(안전장치) |

### 3.2 늦은 응답 폐기 (경합 사례)

| 경합 | 처리 |
|---|---|
| B1 요청 중 비교 종료 → B1 응답 도착 | 종료 시 `compareInflight = null` → seq 불일치로 버린다. 화면은 A 결과 |
| B1 실패 후 B2 위치로 다시 분석, B1 재시도 응답이 늦게 도착 | 재시도도 새 seq를 쓴다. 마지막 요청 seq만 받는다 |
| B 성공 직후 B 위치를 다시 고름 → 이전 B 동종 점포 응답 도착 | `nearbyB`도 별도 seq. 다시 고를 때 abort + `nearbyB = null` → 버린다 |
| 비교 시작 시점에 A 동종 점포가 아직 로딩 중 | A의 요청이므로 그대로 둔다. 비교 중에도 A 점포 데이터로 채워진다 |
| B 응답 좌표·업종이 요청과 다름 | 계약 오류(`schema`)로 표시. A는 그대로 |

## 4. 지도

### 4.1 지도 클릭의 의미

| 상태 | 지도 클릭 | 지도 위 안내(§8.12 오버레이 자리) |
|---|---|---|
| compare off | 지금과 같다(새 위치 선택 → A 결과 지움) | 지금과 같다 |
| picking·error·success | **B 위치 선택**. A는 바뀌지 않는다 | "B 위치를 고르세요 · A: {A 구·동}" |
| loading | 무시 | "B 위치 분석 중…" |

- 점포 마커 클릭은 지금처럼 지도 클릭으로 번지지 않는다(4차 확인 사항 유지).

### 4.2 A/B 표시

MapView props를 이렇게 늘린다. 기존 `selected`·`dong`은 A 의미로 남긴다(호출부·테스트 변경 최소화).

```ts
/** 비교 대상 B (5차). null이면 B를 그리지 않는다 */
compareTarget?: { location: LatLng | null; tone: 'selected' | 'invalid'; dong: { guCode: string; dongName: string } | null } | null
```

| 요소 | A | B |
|---|---|---|
| 마커 | 기존 선택 지점 마커에 글자 "A" (채운 `--color-map-marker`, 흰 글자) | 흰 채움 + `--color-map-marker` 2px 테두리 + 같은 색 글자 "B". 모양과 글자로 구분하고 색만으로 구분하지 않는다(§15). 새 색 토큰은 만들지 않는다(12장 D7) |
| 크기 | 글자가 들어가도록 지름 20px(현재 16px). 비교 중일 때만 글자 마커를 쓰고, off이면 지금 마커 그대로 | 20px |
| 반경 500m 원 | 기존 스타일 | 같은 반경, 테두리 점선 간격만 다르게(예: 2 4) |
| 행정동 경계 | 기존 강조 | B 행정동도 같은 스타일로 강조. A와 같은 동이면 polygon을 한 번만 그린다 |
| 분석 불가 B | — | 회색 B 마커, 반경 원 없음(§8.11과 같은 규칙) |
| 범례 | 비교 중이면 "A 기준 위치 · B 비교 위치"를 추가 | |

- **지도 이동**: B를 고르면 B로 `panTo`(zoom 유지, 지금 규칙과 같음). 비교를 끝내면 A로 `panTo`. 자동 `fitBounds`(zoom 변경)는 하지 않는다. 두 위치를 한 화면에 보는 일은 사용자가 직접 확대·축소한다. "두 위치 모두 보기" 버튼은 12장 D3.
- 지도 인스턴스를 다시 만들지 않는다. B 오버레이는 A 오버레이와 같은 방식으로 effect 안에서 만들고 지운다.

### 4.3 동종 점포 목록·마커·정보창의 기준 위치

**한 번에 한 위치만 보인다.** A와 B의 점포 마커를 함께 그리면 반경이 겹칠 때 어느 위치의 점포인지 구분할 수 없고, 목록·정보창·Escape 처리가 두 벌이 된다.

| 상태 | 점포 기준(`storeSide`) | 지도 점포 마커 | 목록 |
|---|---|---|---|
| picking·loading·error | — | **그리지 않는다**(B 위치를 고르는 클릭과 섞이지 않게). A 데이터는 보존 | 패널에 보이지 않는다(A 요약 카드만) |
| success | 기본 B. "점포 기준: [A] [B]" 전환(segmented, `aria-pressed` 버튼 2개) | 고른 기준의 점포만 | 고른 기준의 `NearbyStores` 하나 |
| off(비교 종료) | A | A 점포(지금과 같다) | A 목록(지금과 같다) |

- 섹션 제목: "반경 500m 안 같은 업종 점포 — B {구·동}". 개수 안내는 지금 문구에 기준 위치 이름을 붙인다.
- 기준을 바꾸면 `activeStoreId`를 지운다(정보창 닫힘). 각 위치의 점포 데이터는 캐시해 두고 다시 조회하지 않는다.
- 지도 위 "선택한 점포" 막대 이름에 기준을 붙인다: "B 주변 · {상호}". Escape·닫기·포커스 규칙(§8.14 4차 보완)은 그대로 쓴다.
- 수 검증(`count == 경쟁성.raw.동종점포수`)은 기준 위치의 분석 결과와 비교한다.
- `NearbyStores`는 `key`에 기준 위치(`side`·좌표·업종)를 넣는다. 그래야 전환할 때 펼침 상태가 섞이지 않는다.
- 두 위치의 점포 **수**는 비교 표의 경쟁성 원시값(`동종점포수`)으로 함께 보인다(5.4).

## 5. 비교 화면 (패널)

비교 결과는 패널에서 A 단일 결과 대신 보인다. A 결과 데이터는 상태에 그대로 있다.

### 5.1 순서

| 순서 | 내용 | 비고 |
|---|---|---|
| 1 | `h1#compare-title` "두 위치 비교 · {업종}" (`tabIndex=-1`, B 성공 시 포커스) | 헤더 Context Bar는 "A {구·동} · B {구·동} · {업종}"으로 바꾼다 |
| 2 | 위치 카드 A·B: 구·동, 최근접역 직선거리(§8.5a), 좌표 보기(접힘), B 카드에 "B 위치 다시 고르기" | `LocationSummary` 재사용(내부 id는 `useId`라 겹치지 않음) |
| 3 | 같은 구·동 안내(5.3) | 해당할 때만 |
| 4 | 점수 비교 표: 종합 + 5대 관점(5.2) | 요약의 중심 |
| 5 | 미산출·데이터 차이(5.4) | 해당할 때만 |
| 6 | 주의할 점 A / B(5.5) | 위치별 목록 |
| 7 | 핵심 원시값 표(5.6) | 기본 접힘(disclosure) |
| 8 | 반경 안 같은 업종 점포(4.3) | 기준 전환 |
| 9 | "A 전체 결과 보기" / "B 전체 결과 보기"(6장) | |
| 10 | 데이터 출처·면책 1회(`#data-sources`, 헤더 링크 대상) | 같은 업종이라 출처가 같다 |

- 초보자 접근성의 진입장벽·인허가·입지 규제는 업종에만 달려 있으므로 6번 아래에 한 번만 짧게 보인다. 위치마다 다른 학교 수는 엔진 경고를 통해 5번 위치별 목록에 나온다.

### 5.2 점수 비교 표

```
                 해상도        A 부평1동   B 구월3동   표시용 차이 (A−B)
 종합            —             65.8        59.1        +6.7
 시장성          구            61.6        68.7        −7.1
 고객성          행정동        82.8        91.4        −8.6
 경쟁성          반경 500m     30.2        24.4        +5.8
 입지성          좌표          79.8        79.5        +0.3
 안정성          구 × 업종     73.2        24.8        +48.4
```

- `<table>` + `<caption>` "종합·5대 관점 점수 비교", 열 머리 `<th scope="col">`(A·B는 위치 이름 포함), 행 머리 `<th scope="row">`.
- 순서는 고정(종합 → 시장성 → … → 안정성). 차이 크기순으로 정렬하지 않는다(P3).
- 점수는 엔진 값 그대로 `formatScore`. null은 "미산출"(색 없이 muted 텍스트).
- **표시용 차이 (A−B)** 정의:
  - 두 값이 모두 숫자일 때만 `Math.round(a * 10 - b * 10) / 10`로 계산한다(소수 1자리 엔진 값끼리 뺄 때 부동소수 오차를 피한다).
  - 표기는 `+6.7`, `−7.1`(U+2212), `0.0`. `-0`은 `0.0`이다. 한쪽이라도 null이면 "—"로 두고, 스크린리더용 텍스트는 "미산출이라 계산하지 않음"이다.
  - 셀은 중립색이다. 큰 쪽을 강조하지 않고, 화살표·"우세"·"승"·"더 좋음"·"순위"·"상위/하위 N%"를 쓰지 않는다.
  - 표 아래 안내(`--text-small` muted): "표시용 차이는 두 점수를 뺀 값입니다. 점수는 세부지표 백분위의 가중평균이라 이 차이는 인천 내 순위 차이나 어느 위치가 낫다는 판정이 아닙니다. 비교 대상이 적은 지표(시장성 11개 구, 안정성 업종별 6~11개 구)는 한 칸 차이로도 9~17점이 달라질 수 있습니다."
- 병목·최고 관점: 각 열 점수 옆에 기존 문구 "병목"·"가장 강한 관점"을 작은 라벨로 붙인다(위치별 사실). 병목 점수가 25 미만이면 기존 규칙대로 warning 톤 라벨을 쓴다.
- 해상도 열은 고정 표기다(1.1 표). 시장성·안정성처럼 구 단위 행은 5.3 안내와 연결된다.
- 막대(§6 horizontal bar)를 A·B 두 줄로 겹쳐 보이는 것은 1차 구현에서 넣지 않는다. 표가 숫자를 정확히 전달하고 스크린리더에서도 읽힌다. 시각 보조는 구현 뒤 검토한다(12장 D5).

### 5.3 같은 구·동 안내

context의 `gu_code`와 `dong_name`으로만 판단한다. 표 바로 위 info notice(`--color-info` 아이콘 + 텍스트)로 둔다.

| 조건 | 문구 |
|---|---|
| 같은 행정동 | "두 위치가 같은 행정동({구} {동})에 있습니다. 시장성·안정성은 구 단위, 고객성은 행정동 단위 데이터라 두 위치 점수가 같습니다. 이 비교에서 위치 차이는 경쟁성(반경 500m)과 입지성(좌표)에만 나타납니다." |
| 같은 구, 다른 동 | "두 위치가 같은 구({구})에 있습니다. 시장성·안정성은 구 단위 데이터라 두 위치 점수가 같습니다." |
| 다른 구 | 없음 |

- 안정성이 한쪽이라도 미산출이면 안정성 문구를 빼고 "시장성은 …"으로 쓴다.
- 같은 이유로 같은 점수인 행에는 해상도 셀에 "같은 구 데이터" 또는 "같은 동 데이터" 라벨을 붙인다(점수 비교가 아니라 context 비교로 붙인다).
- **반경 겹침**: A–B 직선거리 d < 2 × 반경(1,000m)이면 "두 분석 반경이 겹칩니다(A–B 직선거리 {d}m). 겹친 구역의 점포는 두 위치의 경쟁성에 함께 들어갑니다."를 덧붙인다. d는 표시용으로 frontend에서 haversine으로 계산하며 점수에는 쓰지 않는다(12장 D8).

### 5.4 미산출·데이터 차이

위치별로 다음을 보인다. 둘 다 해당이 없으면 섹션 전체를 숨긴다.

- **관점 미산출**: "B: 안정성 미산출 — {notComputedText}"(기존 `notComputedText` 재사용).
- **종합 계산 범위가 다름**: `적용_가중치` 키 집합이 A·B에서 다르면 "B의 종합 점수는 안정성을 빼고 나머지 4개 관점 가중치를 다시 나눠 계산했습니다. 두 종합 점수는 같은 관점 묶음의 가중평균이 아닙니다."라고 쓰고, 종합 행 차이 셀에 각주 표시(†)를 단다.
  - 재현 예: 강화군 강화읍 · PC방은 안정성 None(3년 표본 21 < 30, `SCORE_EXPLANATION_AUDIT.md` 4장). 부평역 · PC방과 비교하면 이 경우가 된다.
- **데이터 충족률**: `종합.데이터_충족률`이 다르면 두 값을 나란히 쓴다.
- **신뢰도 낮음·해상도 저하**: 기존 `dataLimits` 결과를 위치별로 쓴다(5.5와 합친다).

### 5.5 주의할 점

- 2열(desktop) 또는 A 다음 B(mobile)로, 위치별로 `displayWarnings` + `dataLimits`를 보인다. 엔진 경고 문장은 기존 규칙(병목 경고 1개 교체) 외에는 바꾸지 않는다.
- 경고가 없으면 "특별한 경고가 없습니다."를 위치별로 쓴다.
- 같은 문장이 양쪽에 있어도 합치지 않는다(어느 위치의 사실인지가 중요하다).

### 5.6 핵심 원시값 표 (기본 접힘)

관점마다 대표 raw 키만 뽑는다. 값은 엔진 값 그대로이며 단위만 붙인다. **원시값에는 차이 열을 두지 않는다**(단위가 섞이고, 원시값 차이가 점수 차이를 설명한다고 오해하기 쉽다).

| 관점 (단위) | raw 키 → 표기 |
|---|---|
| 시장성 (구) | `일평균_유입인구` 명, `시간대_적합도`(1.0 = 24시간 균등 기준), `상권성격_적합도` |
| 고객성 (행정동) | `타겟연령_거주인구` 명, `타겟연령_비중` %, `종사자수` 명, `1인세대_비중` % |
| 경쟁성 (반경 500m) | `동종점포수` 곳, `점포당_잠재수요`, `동종업종_비중` % |
| 입지성 (좌표) | `최근접역` + `최근접역_거리m`(직선거리), `역세권_강도`, `유인시설_근접도` |
| 안정성 (구 × 업종) | `3년_생존율` %, `최근_폐업률` %, `평균_업력_년` 년 |

- null은 "데이터 없음". 비율 값(0~1)은 `formatRatio`로 %로 바꾸고 나머지는 숫자 그대로 쓴다.
- `타겟_정의` 같은 업종 공통 값은 표 캡션에 한 번 쓴다.
- 이 키 목록은 frontend 상수 하나(`lib/compare.ts`)에 두고, 키가 응답 schema에 있는지 테스트로 고정한다.

## 6. DOM id 충돌

현재 결과 화면의 고정 id: `result-title`, `overall-caption`, `perspectives-title`, `warnings-title`, `access-title`, `nearby-title`, `details-title`, `data-sources`, `sources-title`.

원칙:
1. **`AnalysisResult`는 한 번에 하나만 마운트한다.** 비교 화면은 이것을 두 번 띄우지 않는다. 위치별 전체 결과는 "A 전체 결과 보기"·"B 전체 결과 보기"로 연다. 이 버튼은 패널을 그 위치의 단일 결과 화면(기존 `AnalysisResult`)으로 바꾸고, 맨 위에 "비교로 돌아가기"를 둔다(비교 상태는 유지). 그래서 기존 고정 id를 고치지 않아도 된다(12장 D6).
2. 비교 화면 새 컴포넌트의 id는 `useId` 또는 비교 화면에서 유일한 `compare-*`만 쓴다.
3. `WarningPanel`(고정 `warnings-title`)은 비교 화면에서 위치별로 두 번 쓰지 않는다. 대신 `displayWarnings`·`dataLimits`를 export해서 비교용 컴포넌트가 쓴다.
4. `NearbyStores`(고정 `nearby-title`)는 기준 위치 하나만 마운트하므로 겹치지 않는다.
5. `DataSources`(`data-sources`)는 비교 화면에 한 번만 둔다.
6. 테스트로 고정한다: 비교 화면 렌더 후 `document.querySelectorAll('[id]')`의 id가 모두 유일하고, 모든 `aria-labelledby`·`aria-controls`·`aria-describedby`·`href="#…"` 대상이 정확히 1개 존재한다. 단일 결과 화면에도 같은 검사를 추가한다.

## 7. 모바일 배치 (< 640px)

화면은 지금처럼 `map` / `panel` 둘이다(§14 "지도와 결과를 한 화면에 좁게 넣지 않는다").

| 단계 | 화면 | 하단 sheet / 패널 |
|---|---|---|
| "다른 위치와 비교" | map | sheet: "B 위치: 지도를 눌러 고르세요 · A {동}" + [좌표 직접 입력](패널로) + [비교 취소] |
| B 선택 | map | sheet: "B 선택됨 · {좌표}" + [B 분석하기] (primary) |
| B 분석 중 | map | sheet: "B 위치 분석 중…"(aria-live) |
| B 성공 | panel | 비교 화면. sticky 헤더 "A {동} · B {동} · {업종}" |
| B 실패 | panel | B 카드 안 ErrorBlock + [다시 시도] [B 위치 다시 고르기] |
| 결과에서 지도 보기 | map | sheet: "A {동} · B {동}" + [비교 보기] |

- 점수 비교 표는 375px에서 4열(항목 64px · A · B · 차이)이 들어간다. 해상도 열은 mobile에서 행 머리 아래 caption 줄로 내린다. 페이지 가로 스크롤은 금지(§14). 원시값 표만 내부 가로 스크롤 + 첫 열 고정을 허용한다.
- 주의할 점·위치 카드는 A 다음 B 세로 배치로 둔다.
- 버튼은 모두 44×44px 이상이다. 지도 위 "선택한 점포" 막대(bottom `--space-12`)와 sheet가 겹치지 않는지 브라우저에서 확인한다(4차와 같은 방법).
- tablet(640–1023)은 지도 위·패널 아래 구조 그대로다. 비교 표와 주의할 점 2열은 640px 이상에서 쓴다.

## 8. 키보드·접근성

- **B 선택의 키보드 대안**: 지도 클릭과 같은 기능으로 B 카드에 좌표 입력 폼을 둔다(기존 `CoordinateForm` 재사용 — 지금은 `ConditionPanel.tsx` 내부 함수라 export가 필요하다, 라벨 "B 위도"·"B 경도"). §15 "지도 클릭 선택에는 키보드 대안" 규칙을 따른다.
- **포커스 이동**:
  - "다른 위치와 비교": desktop·tablet은 B 카드 제목(`h2`, `tabIndex=-1`)으로. mobile은 지도 화면으로 바뀌므로 sheet의 첫 버튼으로.
  - B 성공: `#compare-title`. A의 `#result-title` effect는 A 상태가 바뀔 때만 돌게 해 B 성공 때 포커스를 빼앗지 않게 한다.
  - B 실패: ErrorBlock `role="alert"`으로 알리고, 포커스는 B 카드 "다시 시도"로.
  - 비교 종료·취소: "다른 위치와 비교" 버튼으로 돌아간다(누른 자리로 복귀).
  - "B 위치 다시 고르기": B 카드 제목으로.
- **Escape**: 지금처럼 점포 정보창 닫기에만 쓴다. 비교 종료에 Escape를 쓰지 않는다(실수 한 번으로 B 결과를 잃지 않게).
- **표 읽기**: 셀 순서가 "시장성 / A 부평1동 61.6 / B 구월3동 68.7 / 표시용 차이 −7.1"로 읽히게 한다. 차이 셀에는 visually-hidden 텍스트 "A에서 B를 뺀 값"을 둔다. U+2212 기호를 스크린리더가 "마이너스"로 읽지 않을 수 있으므로 hidden 텍스트에 "마이너스 7.1"을 쓴다.
- **로딩·상태 알림**: "B 위치 분석 중…"과 B 동종 점포 로딩은 `aria-live="polite"`.
- **색만으로 구분 금지**: A/B는 지도 마커 글자·표 열 머리·카드 제목의 텍스트로 구분한다.
- **점포 기준 전환**: `role="group"` + `aria-label="점포 기준 위치"` 안에 `aria-pressed` 버튼 2개(Tab·Enter·Space).

## 9. API·엔진

- 새 backend 경로를 만들지 않는다. B는 `POST /analyze`, B 점포는 `POST /nearby-stores`를 같은 body 형식으로 부른다. backend·엔진·schema 변경은 없다.
- 오류 처리는 기존 `errorView`를 쓰되, 비교에서는 행동을 이렇게 바꾼다.
  - `retry` → B 다시 시도
  - `reselect-location` → B 위치 다시 고르기
  - `reselect-business`·`reselect-conditions` → 비교 안에서는 업종을 바꿀 수 없으므로 "비교 취소"로 안내한다. A가 같은 업종으로 성공했으므로 `invalid_business`는 정상 흐름에서 나오지 않는다.
- 분석 불가 코드(`invalid_coordinate`·`location_outside`·`no_data_nearby`)이면 B 마커는 회색이 된다(§8.11).
- 요청은 A 1회 + B 1회(+ 점포 각 1회)다. warm 뒤 분석은 1회 약 0.3s(TASKS 5-2 B4)라 동시 요청 최적화는 필요 없다.
