# 첫 방문 안내 설계안 — 묶음 D 온보딩 (2026-10-19, 설계안 · 구현 전)

> 계획 `docs/IMPROVEMENT_PLAN_2026-10.md` 2-6·§3(묶음 D). 기준 화면은 A3(`DESIGN.md` §19.1·§19.7, 묶음 A·B 반영본). 지도 가독성 보류(9-A5)와 현재 발행값은 건드리지 않는다.
> 원칙: **기본 화면의 글을 늘리지 않는다.** 안내는 첫 방문 1회의 말풍선과 "다시 보기"로만 보이고, 이미 있는 설명(조건 패널 부제, 지도 안내 칩, 반경 안내, "이 점수는?", P1 면책)은 그대로 두고 **중복하지 않는다**.

## 1. 방식

코치마크(화면 요소에 붙는 말풍선) 3단계 + 결과 첫 표시 때 1단계. 진입 모달·전체 화면 튜토리얼은 두지 않는다(분석을 막고 반복 노출 위험, 계획 2-6 비교).

| 단계 | 언제 | 붙는 요소(기존 id·그룹) | 문구(초안, 각 1~2문장) |
|---|---|---|---|
| ① 위치 | 첫 방문, 조건 패널(desktop)·지도 화면(mobile) | 위치 입력 segmented `role=group "위치 입력 방법"` (mobile은 지도 시트의 같은 segmented) | "지도를 누르거나 주소·좌표로 위치를 고릅니다. 인천 안에서만 분석됩니다." |
| ② 업종 | ①을 넘기거나 위치를 고른 뒤 | 업종 `combobox "업종 선택"` | "29개 업종 중 하나를 고릅니다." |
| ③ 분석 | ②를 넘기거나 업종을 고른 뒤 | "분석하기" 버튼 | "다섯 관점 점수로 봅니다. 순위·매출 예측이 아닌 참고 지표예요." (P1 문장 축약 재사용) |
| ④ 결과 | 첫 분석 결과가 처음 보일 때 1회 | 조건 바의 반경 버튼 묶음(`section "분석 반경"`, v0.4 서버에서만) · "다른 위치와 비교" 버튼 | "반경(300·500m·1km)을 바꾸거나, 다른 위치와 비교해 볼 수 있어요." 반경 묶음이 없으면(v0.3 서버) 비교 버튼만 가리키고 문구에서 반경을 뺀다 |

- 말풍선 1개씩, 다음 단계는 "다음" 또는 **해당 행동을 실제로 하면** 자동 진행(위치를 고르면 ①→②, 업종을 고르면 ②→③). ③은 "분석하기"를 누르면 닫힌다.
- 사용자가 말풍선 없이 스스로 진행해도 방해하지 않는다: 말풍선은 요소 옆에 작게(최대 폭 280px, `--color-surface`, 1px `--color-map-ui-edge`, `--shadow-map-ui`, 꼬리 8px), 화면을 어둡게 덮지 않는다.
- 문구에 점수 해석·관점 설명·데이터 설명은 넣지 않는다 — 그건 "이 점수는?"·설명 펼침·상세 근거 탭의 몫이다(중복 금지).

## 2. 건너뛰기·다시 보기

- 모든 말풍선에 "건너뛰기"(이번 안내 전체 종료)와 "다음"(마지막은 "확인"). 건너뛰기·완료 모두 `localStorage` `onboarding = done`(테마와 같은 저장 방식, 실패해도 세션 동안은 상태 유지).
- ④ 결과 안내는 별도 키 `onboarding.result = done`. **2026-10-31 개정(팀 점검 D7)**: 안내는 첫 방문 한 번의 흐름 — 건너뛰기는 ④까지 끝내고(두 키 모두 done), ④는 진행 중인 ①~③에 이어질 때만 보인다(예전에 안내를 마친 사용자의 첫 결과에서 따로 뜨지 않음). 공유 링크로 바로 결과에 온 첫 방문은 ④만 보고 ①~③은 끝낸 것으로 한다. 다시 보기는 `?` 버튼.
- **다시 보기**: "이 점수는?" 옆 결과 머리와 조건 패널 머리("새 분석" 줄 오른쪽)에 아이콘 버튼 1개 "사용 방법"(`aria-label`, 기존 line 아이콘 `info` 또는 새 `help-circle`). 누르면 지금 화면에 맞는 단계부터 다시 시작한다(분석 전이면 ①, 결과면 ④). 버튼 하나만 늘고 글은 늘지 않는다.
- 저장값 삭제(=첫 방문 재현)는 개발자 도구로만. 설정 화면은 두지 않는다.

## 3. 모바일 흐름 (≤639px)

- 첫 진입은 지도 화면 + 하단 시트(접힘). ①은 시트의 segmented 위에 붙는다(시트 안쪽, 지도 가림 없음). 지도를 눌러 위치를 고르면 시트 문구가 "이 위치로 계속"으로 바뀌는 기존 흐름 그대로 → 그 버튼을 누르면 패널 화면에서 ②가 업종 select 옆에 붙는다 → ③ "분석하기". 시트 ①의 "다음"은 ②가 있는 **조건 패널 화면으로 함께 전환**한다 — 지도 화면에 남으면 ②와 업종 select가 숨겨진 패널에 있어 안내가 사라진다(Codex 검수 지적, 9-R2).
- ④는 결과 지도 화면의 시트([결과 자세히][다른 위치와 비교] 버튼 줄)에 붙인다. 반경 버튼은 mobile에서 조건 바 둘째 줄에 있으므로 문구는 같되 화살표는 비교 버튼만 가리킨다.
- 말풍선은 시트·패널의 스크롤 흐름 안에 들어가는 **인라인 요소**로 두어(절대 위치 아님) 작은 화면에서 잘리지 않게 한다. 폭은 시트 폭을 따른다.
- 지도 가림 금지: 지도 위에는 말풍선을 두지 않는다(범례·안내 칩·저작권 띠와 겹치지 않게).

## 4. 키보드·접근성

- 말풍선은 `role="dialog"`가 아니라 `role="status"` + `aria-live="polite"`로 읽히는 **비모달** 요소. 포커스를 가로채지 않는다 — 사용자가 Tab으로 가던 요소 순서를 바꾸지 않는다.
- 말풍선 안 버튼("다음"·"건너뛰기")은 붙은 요소 **바로 다음** 탭 순서에 온다(DOM상 그 요소 뒤에 둔다). Escape는 현재 말풍선을 닫되 안내 전체를 끝내지는 않는다(건너뛰기와 구분).
- 다시 보기 버튼은 44px, `aria-label="사용 방법 다시 보기"`. 말풍선이 열리면 그 문구가 `aria-live`로 읽힌다.
- `prefers-reduced-motion`이면 나타나는 애니메이션 없음(§12 규칙 그대로).
- 스크린리더 실기기 확인은 미검증 범위로 남긴다(기존 묶음과 동일).

## 6. 결정이 필요한 점

1. ④ 결과 안내를 ①~③과 **별도 1회**로 둘지(위 설계), 아니면 ①~③을 끝낸 사용자에게만 보일지.
2. 다시 보기 버튼 자리: "이 점수는?" 옆(결과)과 "새 분석" 머리(조건) 2곳 — 1곳(조건 머리)만 둘 수도 있다.
3. 문구 톤: 위 초안은 기존 화면과 같은 "~요/~합니다" 혼용 없이 "~합니다"로 통일할지.
