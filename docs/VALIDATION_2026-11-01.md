# 사후검증 재현과 검증 설계 (TASKS 12-24, 2026-11-01)

이 문서의 수치는 **과거 개업 코호트와의 사후 연관**이며 예측 성능이 아니다. 엔진·golden·`data/runtime`·`sources/`는 바꾸지 않았고, 운영 화면과 점수에도 변경이 없다.

## 1. 결론

- 운영 엔진 v0.5.1의 안정성 제외 4관점 점수와 실제 3년 생존율 사이에서 **일관된 관계를 확인하지 못했다.** 음식 9개 업종 평균 ρ는 −0.067이고, 95% 구간(2km 블록)은 −0.179~+0.042로 0을 포함한다.
- 분동 인구비 결함을 고친 v0.5.1은 v0.5(−0.068)와 사실상 같다. 종합 점수가 4,582칸 중 2,545칸에서 바뀌었지만(최대 11.5점), 생존율과의 상관은 거의 움직이지 않았다.
- 인구·점포 수 같은 **단순 기준보다 낫다는 근거도, 못하다는 근거도 없다.** 비교한 단순 기준의 차이 구간이 모두 0을 포함한다.
- 따라서 "점수가 높으면 더 오래 살아남는다"고 말할 수 없다. 화면의 "매출이나 성공 확률을 뜻하지는 않아요"와 AI의 성공 확률 표현 금지는 그대로 유지하며, 이번 결과로 점수·계수를 바꾸지 않는다.

## 2. 무엇을 어떻게 재현했나

| 항목 | 내용 |
|---|---|
| 스크립트 | 팀 `busy_bias_check.py`·`survival_validation.py`를 바이트 그대로 복사해 실행(`scripts/survival_repro.py`, 해시 대조). 팀 `run_all.py`는 복사·실행하지 않음 |
| 작업 위치 | `.gstack/validation-12-24/<엔진>/`(git 제외). 원본 폴더에 쓰지 않음 |
| 엔진 | `scoring_engine/v0_5`(대조군)·`scoring_engine/v0_5_1`(운영 엔진) + 팀 인허가 보조 모듈 |
| 점수 입력 | `data/runtime` + SGIS 2025 2분기 경계. **운영 데이터 2026-09가 아니다** — 팀 스크립트가 `패널_시장성_202608.csv`를 파일 이름으로 읽어 그대로 돌리려면 이 자료여야 한다 |
| 결과 자료 | 행안부 인허가 일반·휴게음식점(인천, 관측 기준일 2026-09-29), 2013-01-01 이후 개업하고 3년이 지난 업소 23,200건 |
| 표본 규칙 | 158개 동 중심점 반경 500m, 개업 10건 이상인 동, 동 15곳 이상인 업종, 안정성 제외(안정성은 같은 인허가 자료로 만들어 정답 누출) |

**대조군 결과: 재현됨.** 같은 방식으로 v0.5를 돌리면 팀 결과와 다음처럼 일치한다.

- 4,582칸(158×29)의 관점 점수 5개와 번화가 값이 모두 같고, 업종별 ρ 9개와 평균 −0.069도 같다.
- 종합 점수만 67칸에서 0.1 다르다. 67칸 모두 정확값이 반올림 경계(x.x5)에 있는 칸으로, 부동소수점 차이다. 이 재현이 쓰는 4관점 점수에는 영향이 없다.
- 평균 표기 차이: 팀 방식(소수 둘째 자리로 반올림한 뒤 평균)은 v0.5 −0.069·v0.5.1 −0.068이고, 이 문서의 분석(반올림 없이 평균)은 v0.5 −0.068·v0.5.1 −0.067이다.

### 3-3. 코호트 민감도 (v0.5.1)

- 2013~2017 개업과 2018년 이후 개업으로 나눠도 평균은 −0.066·−0.070으로 비슷하다. 다만 표본 규칙을 넘는 업종(6개·5개)과 동이 달라 두 평균을 직접 비교할 수 없다.
- 양쪽에 모두 있는 업종은 카페 −0.081 → −0.353, 생맥주 +0.018 → −0.156, 김밥 −0.163 → −0.102, 백반 −0.045 → −0.045다.
- 코호트 안에 종료일을 모르는 건은 0건이라 이 처리의 영향은 없다.

## 4. 이 결과의 한계

1. **입력이 결과보다 뒤 시점이다.** 점수는 2026년 무렵 자료인데 코호트는 2013~2023년 개업이다. 살아남은 점포가 2026년 상가 자료에 남아 경쟁성·번화가 값에 다시 들어가므로, 원인과 결과를 구분할 수 없다.
2. **29개 업종 중 음식 9개만 봤다.** 나머지 20개 업종은 이 방식의 검증이 없다.
3. **동 중심점 점수다.** 개별 점포 자리의 점수가 아니고, 중심점과 점포는 최대 500m 떨어져 있다.
4. **이웃 동의 반경이 겹친다.** 중심점 간 거리 중앙값 787m, 67.1%의 동이 1km 안에 이웃을 두고, 반경에 든 개업의 20.0%가 2개 동 이상에 중복으로 세인다. 블록 재표본이 일부 반영하지만 완전히 없애지는 못한다.
5. **표본 규칙이 범위를 좁힌다.** 개업 10건 이상인 동만 남아 사람이 적은 지역은 빠지고, 동별 개업 수가 14건 안팎인 업종은 생존율 자체가 흔들린다.
6. **생존의 뜻이 좁다.** 인허가상 3년 유지일 뿐 수익·이전·양도를 구분하지 못한다.
7. **운영 데이터와 다르다.** 2026-09 자료로는 돌리지 않았다.

## 5. 검증 설계 6항

| 항목 | 설계 | 이번 상태 |
|---|---|---|
| 1. 목적 분리 | **설명**: 점수의 근거를 자료로 추적할 수 있는가(golden·AI 수치 대조). **비교**: 같은 조건에서 두 후보의 차이를 설명할 수 있는가(반경 표·과제 테스트). **예측**: 미래 결과를 맞히는가(지금은 주장하지 않음). 문구와 지표를 목적별로 섞지 않는다 | 정의함. 예측 목적의 근거는 **없음** |
| 2. 시간 분할 | 입력을 먼저 고정하고 그 **뒤** 개업한 코호트만 본다 | **불가, 미실시.** 보유 입력 스냅샷이 2026년뿐이다. 6장 참고 |
| 3. 공간 블록 | 반경이 겹치므로 동을 독립 표본으로 세지 않는다. 불확실성은 2km 블록(반경 1km 분석이면 블록도 키움), 모델을 학습하게 되면 블록 단위로 평가한다 | 부트스트랩 적용. 엔진이 학습 모델이 아니라 평가 분할은 불필요 |
| 4. 베이스라인 | 인구·점포 수만 / 4관점 / 관점 제외와 **같은 재표본**으로 비교한다. 단순 기준을 이기지 못하면 예측력을 말하지 않는다 | 적용(3-2). 차이 구별 안 됨 |
| 5. 업종별 공개 | 평균 하나로 말하지 않고 표본·상관·구간을 업종별로 낸다. 빠진 업종과 보정 여부도 적는다 | 적용(3-1). 다중 비교 미보정을 명시 |
| 6. 과제 테스트 | 7장 절차로 사람이 화면을 쓰며 확인한다 | **미실시.** 참가자 필요 |

## 6. 앞으로 시간 분할을 하려면

과거로 돌아가 입력을 만들 수 없으므로 지금부터 쌓는 전향적 방식이 가장 정직하다.

1. 입력을 고정한다: `data/versions/2026-09`와 이 시점 엔진 v0.5.1. 이 폴더는 git 밖이므로 별도 보관이 필요하다.
2. 인허가 원본을 주기적으로 받아 보관한다. 지금은 2026-09-29 관측본 하나뿐이다.
3. 2026-10 이후 개업을 코호트로 삼아, 1년 결과는 2027-10 이후, 3년 결과는 2029-10 이후에 본다.
4. 분석 규칙(표본 기준·블록·베이스라인)은 `scripts/survival_analysis.py` 그대로 쓰고, 결과를 본 뒤 바꾸면 바꿨다고 적는다.

과거 시점의 상가·인구 자료를 구할 수 있다면 소급 분할도 가능하다. 다만 지금 저장소에는 없고, 구할 수 있는지도 아직 확인하지 않았다.

## 7. 예비창업자 과제 테스트 절차 (미실시)

- **대상·방식:** 예비창업자 또는 창업 관심자 3~5명, 각 20분 안팎. 운영 화면을 쓰고 설명은 하지 않는다. 답과 막힌 지점을 적고 개인정보는 남기지 않는다.
- **과제 1, 후보 차이 설명:** 같은 업종으로 두 후보를 비교하게 한 뒤 "어디가 왜 다른지" 묻는다. 관점과 근거 숫자를 들어 말하면 통과.
- **과제 2, 결측 인지:** 안정성이 없는 업종(네일숍 등)에서 "이 점수에 빠진 자료는?"을 묻는다. 안정성·임대료 등 빠진 자료를 하나 이상 말하면 통과.
- **과제 3, 다음 행동:** 결과를 보고 "계약 전에 무엇을 하겠는가"를 묻는다. 규제 확인·현장 확인처럼 구체적인 행동을 말하면 통과.
- **공통 확인:** "이 점수가 높으면 망하지 않는다는 뜻인가?"를 마지막에 묻고, 성공 확률로 이해한 사람 수를 센다.
- **판정 기준:** 과제별로 과반이 통과하지 못하거나, 성공 확률로 이해한 사람이 1명이라도 있으면 해당 문구를 고칠 후보로 올린다. 인원이 적어 통계적 주장은 하지 않는다.
