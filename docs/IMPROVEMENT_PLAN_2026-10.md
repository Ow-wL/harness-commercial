**제안 구조 — 데이터 버전 전환(덮어쓰기 금지)**

```
data/runtime/            ← 현재: 원본 사본(불변, 해시). 앞으로 "v2026-06 데이터 버전"의 별칭
data/versions/<id>/      ← 새 버전. id 예: 2026-09 (상가 2026-09-30 기준 파일이 들어오는 시점의 묶음)
  manifest.json          파일별 sha256 · 출처 URL · 포털 등록일 · 자료 기준일 · 수집일 · ETL 스크립트 버전 · 검증 결과
  <8개 런타임 파일>       컬럼·인코딩·키 규칙은 지금과 동일(스키마 변경 금지)
scripts/etl/             원본 etl_*.py의 실행 사본(원본과 diff 기록) + 수집(fetch) + 검증(validate) + 버전 생성(build_version)
```

- **로더**: `load_runtime(data_dir)`는 이미 디렉터리 인자를 받는다. 환경변수 `DATA_VERSION`(기본 = 현재 `data/runtime`)으로 디렉터리를 고르고, `RUNTIME_FILES`의 고정 파일명(`패널_시장성_202608.csv`)은 매니페스트의 역할 키(`market_panel`)로 찾는다. 엔진·점수 공식은 그대로다.
- **검증(적용 전 필수, 실패 시 기존 버전 유지)**: 스키마·인코딩·필수 컬럼(`tests/test_data_runtime.py` 재사용) → 키 규칙(행정동 158개 = 패널 158개, `시군구코드 == 행정동코드[:5]`, 업종 29개 컬럼) → 경계 polygon↔점포 라벨 일치율 floor(D-010, 지금 98.46%) → 변화량 한계(점포 수 ±20%, 인구 ±5% 등 넘으면 수동 확인) → 부평역 29업종 결과를 이전 버전과 **차이 보고서**로 비교(점수 변화는 정상, 미산출·오류·NaN이 늘면 실패).
- **golden과의 관계(결정 필요, D-006 개정)**: v0.3·v0.4 golden은 **데이터 2026-06 + 엔진**의 조합이다. 데이터 버전을 바꿔도 이 golden은 그대로 `data/runtime`(2026-06)으로 계속 통과시킨다. 새 데이터 버전에는 golden 대신 (a) 위 검증 + (b) 부평역 29업종 스냅샷을 매니페스트에 기록해 다음 버전과 비교한다. 즉 **데이터 버전은 엔진 버전과 다른 축**이며, 엔진 상수가 바뀌어야 하는 갱신(임대료 분기)만 엔진 버전으로 다룬다.
- **적용과 복구**: 새 버전은 **새 이미지 → Cloud Run 새 리비전(무트래픽 → warm 87/87 → 전환)** 으로만 적용한다. 실행 중 프로세스에서 파일을 바꾸지 않는다. 복구는 이전 리비전으로 트래픽 전환(지금 배포 절차와 동일). 이러면 `ReferenceCache`·`RuntimeData` 무효화는 자동이다(프로세스가 새로 뜬다). 멀티 워커·디스크 캐시는 지금처럼 미도입(D-016).
- **캐시·비교 기준**: `/health`에 `data: {version, as_of: {...}}`를 더하고, `/analyze`·`/nearby-stores` 응답에도 데이터 버전을 넣는다. 프런트 결과 캐시 키와 A·B 대조(지금 엔진 버전 대조 S5·S8)에 데이터 버전을 추가해 **서버가 바뀌면 캐시 폐기 → 재조회**(기존 R1/R2 복구 경로 재사용). 비교 모집단(158개 중심점·백분위)은 데이터와 함께 바뀌는 것이 맞으며, A·B가 다른 데이터 버전으로 계산되면 비교 계약 오류로 다룬다(엔진 버전과 같은 규칙).
- **자동화 범위(추천: 반자동)**: 수집·검증·차이 보고서까지 자동(월 1회 스케줄, 상가 분기 파일 등록 후), **적용(이미지 빌드·리비전 전환)은 사용자 승인**. 완전 자동 적용은 포털 스키마 변경·인코딩 함정(원본 `prep.py` 주석의 사례)이 조용히 틀릴 위험이 있어 권하지 않는다. 포털 로그인·파일 다운로드 자동화는 포털 약관·봇 차단을 확인한 뒤 결정한다 **[추정]**.

### 2-3. 인천 외곽선과 업종별 점포 아이콘

- **외곽선**: 위 2-2의 union 결과. 위계는 **인천 외곽 2px 실선(가장 진함) › 구 경계 1px 실선(중간) › 분석 행정동 1.5px 점선(기존)**. 서비스 범위 밖을 옅게 덮는 토큰 `--color-map-outside-dim`이 §2.6에 이미 정의돼 있다(미사용) — 외곽선 polygon을 구멍으로 둔 큰 사각형 하나로 구현 가능. 다만 외곽선이 행정 경계라 **바다·섬 사이 해역이 "인천 안"으로 보인다**. 해안선 데이터는 없으므로 (a) 행정 경계 그대로 + 범례 설명, (b) 외곽선만 그리고 dim은 생략 중 스파이크 캡처로 고른다 **[추정]**.
- **업종 아이콘**: 29업종을 10~12개 글리프로 묶는다(카페 / 음식·분식 / 주점 / 치킨·피자·버거 / 편의점·슈퍼 / 미용·네일·피부 / 학원·독서실 / PC방·게임·당구·노래 / 운동 / 세탁 / 약국). 세트는 **Lucide(ISC) 1개로 고정**(§13 line·24 grid·stroke 조정 가능, 저작권 고지 포함) [확인]. 렌더는 지금처럼 HtmlIcon + inline SVG(CSS 토큰으로 두 테마 색).
- **겹침·성능 [확인/추정]**: 행정동 1곳의 같은 업종 점포 최대 230곳(카페), 145곳(미용실)이라 1km 반경에는 수백 개가 들어올 수 있다 **[추정: 패널 동별 수 기준]**. 규칙: **≥15 아이콘(24px) / 13~14 작은 아이콘(16px) 또는 점 / ≤12 점(지금)**, 같은 줌에서 N ≥ 80이면 점으로 내린다(단순 임계, 클러스터링 없음). - **구분**: 분석 위치 A·B는 기존 글자 마커(모양이 다르다), 선택 점포는 아이콘 + 바깥 링 + `zIndex` 최상, 일반 점포는 아이콘만. 색만으로 구분하지 않는다(기존 원칙).
- **접근성**: 마커는 `title`(상호), 키보드 경로는 기존 점포 목록. 아이콘 의미는 범례 1줄("같은 업종 점포 = 업종 아이콘").

### 2-4. 점포의 네이버·구글 연결

- **정확한 매칭 가능성 [확인]**: 데이터에는 상가업소번호·상호·주소·좌표만 있다. 네이버·구글 장소 ID가 없고, 상가업소번호는 두 서비스의 ID가 아니다(간주 금지). Geocoder 서브모듈은 좌표↔주소만 준다. → **정확한 상세 페이지 연결은 불가**, 검색 링크로 간다.
- **Google [확인]**: `https://www.google.com/maps/search/?api=1&query=<상호>,<주소>` — 키 불필요, URL 인코딩, 2,048자 제한, 모바일은 앱으로 열림.
- **NAVER**: 공식 문서는 **앱 URL Scheme** `nmap://search?query=…&appname=…`, `nmap://place?lat=…&lng=…&name=…&appname=…`만 있고 앱 설치가 필요하다(모바일) [확인]. 웹 `map.naver.com/p/search/<검색어>`는 공식 규격이 없고 이 환경에서 접속 확인도 못 했다 **[추정 → 사용자 브라우저에서 실측]**. 제안: 웹 링크를 기본으로 두고(실측 통과 시), 모바일에서는 `nmap://` 시도 후 미설치면 웹 링크로 — 공식 안내대로.
- **표시 위치**: 점포를 **선택했을 때만** 정보창과 목록 선택 항목에 "네이버 지도 · 구글 지도" 두 링크(`target=_blank rel=noopener`). 정보창은 DOM 생성이라 안전하게 붙일 수 있다. 문구: "검색 결과로 열립니다(같은 가게가 아닐 수 있음)".

### 2-5. 다크·라이트 모드 전환

- **구조 [확인]**: `tokens.css`(밝은 §17) 위에 `tokens-a3.css`(다크)가 전부 덮는다. 제안: 다크 덮어쓰기를 `:root[data-theme="dark"]`로 묶고, `data-theme="light"`일 때는 §17 토큰 + A3 블루안 라이트 보정(강조·관점색·경고색은 같은 계열, 대비 재측정). 지도 팔레트는 지금처럼 **실제 렌더 톤(`data-map-tone`)** 이 정한다 — UI 테마와 분리 유지.
- **지도 전환**: `customStyleId`는 생성 옵션이고 실행 중 교체가 문서화돼 있지 않다 **[확인: 옵션 설명만]** → 테마 전환 시 **§19.3.1의 지도 재생성 경로**(세대 번호, 오버레이·정보창 재그리기, 위치·반경·결과 유지)를 호출한다. 전환 전에 `getCenter`·`getZoom`을 읽어 새 지도에 넘기고 GL↔래스터 줌 차이(−1)는 기존 환산으로 맞춘다. 비교 A·B·선택 점포·결과 탭은 React 상태라 그대로다.
- **라이트 모드의 지도(결정 필요)**: (a) NAVER 기본 밝은 지도(래스터, 지금의 대체 지도 그대로 — 추가 작업 없음, 라벨 조정 불가) 또는 (b) Style Editor **라이트 테마** 스타일을 사용자가 발행해 GL로 적용(라벨·POI를 다크와 같은 규칙으로 정리 가능, 실패 시 (a)로 복구). 추천 (b), 단 발행은 사용자 작업.

### 2-7. 현재 분석에 질문하는 AI Q&A

- **구조**: 프런트 → `POST /ask` (FastAPI) → Anthropic API. 키는 서버 환경변수(Cloud Run Secret Manager), 프런트에 두지 않는다. 요청에는 **현재 분석 응답(context·result·nearby 요약·반경·엔진·데이터 버전·출처·기준일)과 질문, 같은 분석 안의 이전 대화**만 보낸다. 서버는 보낸 분석이 실제 `/analyze` 결과인지 다시 계산해 대조한다(위변조·환각 방지, 20ms).
- **근거 규칙(시스템 프롬프트 + 구조화 입력)**: 수치는 전달된 값만, 출처·기준일을 함께 말한다. **성공 확률·예상 매출·순위·없는 점포 정보 금지**. 응답은 "① 이 분석에서 보이는 것 / ② 일반적인 창업 참고(분석 밖)" 두 구획으로 나눠 구분한다. 확인 못 하는 질문은 "이 데이터에는 없습니다"로 답한다. 비교 중이면 A·B 둘을 넣는다.
- **대화 맥락**: 대화 키 = (lat, lng, 업종, 반경, 엔진 버전, 데이터 버전). 조건이 바뀌면 **대화를 접고 "이전 분석에 대한 대화"로 표시**, 새 질문은 새 맥락에서 시작(이전 대화를 섞지 않는다). 서버는 대화를 저장하지 않는다(클라이언트가 보낸 이력 재전송, 상한 10턴).
- **비용·속도·제한 (2026-10-06 가격표 기준 [확인], 분석 JSON 약 10KB → 입력 약 8~12k 토큰 [추정], 답 500 토큰)**

## 3. 묶음과 의존관계, 추천 순서

```
묶음 A 지도 기반·테마   = 2-5 테마 전환 + 2-2 라벨·구 경계 + 2-3a 인천 외곽선      (MapView·토큰·build_geo)
묶음 B 점포 레이어     = 2-3b 업종 아이콘 + 2-4 외부 링크                            (MapView 점포 부분·정보창·목록)
묶음 C 데이터 버전     = 2-1 수집·검증·버전 전환 + 기준일 API·표시                   (scripts/etl·backend·data/versions·DataSources)
묶음 D 온보딩          = 2-6                                                          (새 컴포넌트, 화면 확정 뒤)
묶음 E AI Q&A          = 2-7                                                          (backend /ask·질문 패널)

의존:  A ─▶ B (두 테마의 점포 색·아이콘 대비는 테마가 정해진 뒤에 1회만 측정)
       A, B ─▶ D (코치마크가 가리킬 요소·테마가 확정돼야 함)
       C ─▶ E (답의 근거 문장에 데이터 버전·기준일 API가 필요)

       D, E는 서로 독립
```

**추천 순서: A → (C 병행) → B → D → E**

| 순서 | 묶음 | 이유 |
|---|---|---|
| 1 | **A 지도 기반·테마** | 사용자가 직접 지적한 가독성 문제(지역명·구 경계)를 바로 체감. 테마 전환을 먼저 정해야 B·D의 색·대비 작업을 두 번 하지 않는다. 외부 의존이 Style Editor 재발행(사용자) 하나뿐 |

6. AI Q&A: 모델(기본 `claude-opus-5-5`, 비용 우선이면 Sonnet/Haiku), **월 예산 상한**, 질문 원문 로그 미저장 원칙, TASKS "AI 설명" 보류 해제.
