원본 보호와 재현성

H-0 · D-001~D-008
  • 팀 원본 75개 파일을 해시로 고정하고 매 검증마다 확인한다. 원본 실행 스크립트는 golden을 덮어쓰므로 실행하지 않는다.
  • 엔진은 원본과 바이트가 같은 사본으로 둔다. import 방식은 감싸는 패키지 쪽에서 처리해 "같은 엔진"임을 해시로 증명할 수 있다.
  • 부평역 좌표·행정동·임대료 상권 같은 하드코딩은 입력 파라미터로 분리했다.
  • 가중치를 0.01만 바꿔도 golden 테스트가 실패하는 것을 확인했다. golden은 엔진 버전을 올릴 때만 새로 만든다.

좌표를 엔진 입력으로 바꾸는 계층

TASKS 1 · D-009~D-011 · D-015 · D-017
  • 2026년 7월 개편 기준 인천 행정동 경계 158개를 사용한다. 경계의 행정동 코드 158개가 엔진 데이터 158개와 정확히 맞는다.
  • 인천 밖·바다·잘못된 좌표는 각각 다른 오류로 구분하고, 반경 500m 안에 점포가 없으면 분석하지 않는다.
  • 임대료 상권(R-ONE 9곳)은 MVP에서 일반 좌표에 연결하지 않기로 했다. 안정성의 임대료 지표는 "데이터 없음"으로 빠지고 엔진 규칙대로 나머지로 재계산된다.

구월1동·구월3동 경계 교정

구월3동으로 등록된 점포 2,486개가 경계 데이터상 구월1동에 들어가 있었다. 통계청 SGIS 공식 역지오코딩으로 해당 좌표 439개를 조회하니 전부 구월3동이었다. 경계 데이터가 2015년 구역 편입을 반영하지 못한 것이어서, SGIS 공식 경계로 두 동만 교정했다. 엔진·점수 데이터·golden은 바뀌지 않았다.

성능

TASKS 2 · D-013 · D-016
  • 데이터 로드 약 4초, 업종 하나의 비교 모집단 계산 약 2.5초, 29개 업종 전체 약 60초.

  • 계산 결과를 디스크에 저장하는 캐시는 지금 성능으로 충분해 도입하지 않았다.

Backend

TASKS 3 · D-012 · D-014
  • GET /health, GET /businesses(29개 업종, 4개 그룹), POST /analyze.
  • 엔진 결과는 가공하지 않고 그대로 전달한다. API 결과와 엔진 직접 호출 결과가 같은지 테스트로 고정했다.
  • 사용자 입력 문제는 422와 원인 코드, 서버 내부 오류는 500과 추적용 request_id로 응답한다.

Frontend

TASKS 4
