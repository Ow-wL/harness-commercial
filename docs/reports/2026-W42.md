## 4. 디자인 방향 확정

초기 시안에서 개발용 MVP의 정보 밀도와 표현 방식이 충분히 개선되지 않아, 지도·패널·결과 위계를 다시 설계했다. 사용자는 A 지도 탐색형을 선택했고, A2의 구조 개선 뒤 A3의 두 색상안 중 블루안을 선택했다.

- 지도와 선택 위치를 중심으로 구성하고, 결과는 데스크톱 패널·모바일 하단 시트로 표시한다.
- 딥 네이비 배경에 블루는 주 행동·A 위치, 민트는 점포·정보, 라벤더는 B 위치, 로즈는 실제 경고·병목에 사용한다.
- 요약·주변 점포·상세 근거를 분리하고, 긴 출처·방법 설명은 펼쳐서 확인한다.
- 중요한 병목·미산출·데이터 한계는 정보량을 줄여도 유지한다.
- 색 외에도 A/B 글자, 아이콘, 크기와 링 등으로 상태를 구분한다.
- 이 디자인은 목표 설계이며, 현재 운영 화면이 A3로 바뀐 것은 아니다.

## 5. 지도 맞춤 구현과 회귀 수정

### 5.1 단일 지도 맞춤 — 8-B1

지도 클릭·주소·좌표 입력으로 새 위치를 고르면 분석 반경이 실제 지도 사용 영역에 들어오도록 맞춘다. 이미 적절하게 보이면 불필요하게 이동하지 않고, 사용자는 ‘범위에 맞추기’ 버튼으로 다시 맞출 수 있다.

숨김 상태나 SDK init 전에는 맞춤을 미룬다. 사용자가 직접 휠·드래그로 지도를 조정하면 대기 중 자동 맞춤을 취소한다. 분석 완료·점포 선택·화면 크기 변경만으로 zoom을 바꾸지 않는다. 단일 점포 정보창은 사용 영역 안에서 분석 핀을 가리지 않도록 위치를 조정한다.

구현 보고의 production build 측정은 1280·970·800·375·360 폭에서 진행됐다. 원 지름은 사용 영역 짧은 변의 0.53~0.92배였고, 폭마다 점포 12곳의 정보창 배치와 zoom 불변을 확인했다. 실제 터치 기기 확인은 남아 있다.

### 5.2 Codex 검수에서 발견한 회귀 2건

1. 비교 시작과 지도 표시가 같은 렌더에서 발생하면, 미뤄 둔 단일 맞춤이 옛 비교 상태를 읽고 실행됐다. 비교 진입 시 대기 맞춤을 버리고, 지도 표시 처리 전에 최신 상태를 layout effect로 갱신하도록 수정했다.
2. 새 단일 정보창 배치가 비교 화면에도 적용됐다. 단일에만 적용하도록 제한하고, 비교는 8-B2까지 기존 동작을 유지하도록 수정했다.

수정 커밋은 `7e9b8d0`이다. Claude는 회귀 테스트 6건을 추가했고, 수정 전 코드에서 그중 5건이 실패하는 것을 확인했다. Codex는 관련 테스트 3개 파일·85건 통과와 실제 패치를 확인해 재검수를 마쳤다.

## 6. NAVER 다크 지도 스파이크 검증

### 6.1 실제 다크 스타일과 지도 표현

사용자가 Style Editor에서 새 스타일을 발행했다. 실제 GPU(RTX 3060) 브라우저에서 GL 렌더링, 스타일 요청 성공, 실제 다크 화면을 확인했다. 저장만으로 서비스에 반영되지 않았던 POI 설정은 재발행 후 적용됐다.

- 음식점·쇼핑 브랜드 POI는 끄고, 은행·역·출구·건물 이름·공원·랜드마크는 유지했다.
- 건물 AOI 채움 색의 부수 변경은 현재 값 `#58483e`를 유지하고 이력을 기록했다.
- 같은 축척에서 GL zoom은 래스터 zoom보다 1 작았다.
- 1:1 부분 캡처에서 다크 점포 점 대비 최소 3.53, 선택 핀 5.29를 확인했다.
- 밝은 지도 점포 색은 `#066B54`로 조정해 측정 표본에서 최소 대비 3.81(래스터)·4.32(GL)를 확인했다.
- SDK 로고·저작권·축척은 보존하고, 배경 띠로 가독성을 확보했다. 다크 띠는 `rgba(222,229,240,.94)`, 밝은 지도는 기존 흰 띠를 사용한다.

대비 수치는 해당 캡처의 측정 표본 결과이며 모든 위치·축척에서의 보장을 뜻하지 않는다.

### 6.2 스타일 실패 복구

잘못된 스타일 ID에서는 SDK가 밝은 지도로 자동 대체하지 않고 init도 보내지 않는 것을 확인했다. 스파이크에 다음 복구 경로를 추가했다.

- 스타일 요청 실패 또는 보이는 상태에서 init 시간 초과 → 실패 지도·오버레이·리스너 정리 → 스타일 없는 래스터 지도 1회 재생성.
- 밝은 지도도 실패하면 오류로 종료하며 반복 재시도하지 않는다.
- 지도 세대 번호로 늦은 이벤트·응답이 복구 상태를 덮지 않게 한다.
- init 대기 중 숨겨지면 타이머를 취소하고, 다시 보이면 새로 대기한다. 완료·실패·정리 때 해당 리스너를 제거한다.

잘못된 ID는 실제 실패 응답으로 확인했다. init 시간 초과·대체 실패는 검수용 옵션으로, 숨김 전환은 visibilityState 재정의와 이벤트 발생으로 재현했다. 실제 GPU 브라우저에서 실행했지만 실제 창 숨김 동작을 그대로 재현한 시험은 아니다.

**이 복구 로직과 A3 지도 표현은 스파이크 검증 결과다. 제품 적용은 이후 UI 개편 단위에 남아 있다.**

## 8. 남은 작업과 현재 중단 지점

사용자 요청에 따라 이번 주 작업은 기록 정리에서 마친다. 다음 작업은 아직 착수하지 않았다.

1. **8-B2 비교 지도 맞춤:** 두 위치 합집합·B만 맞춤 정책, 사용자 맞춤 버튼, 숨김 중 B 선택·버튼 요청, A/B 핀을 피하는 비교 정보창 배치.
2. **A3 제품 UI 개편:** 확정 레이아웃·블루안·결과 탭·주의 띠 적용, 실제 다크 스타일 및 밝은 지도 복구 적용. 면책 원문 표시 정책은 결정 필요.
3. **추가 검증:** 1440 전체 GL의 1:1 대비, 실제 iOS·Android 터치, 화면 낭독기·한글 입력기 Enter, 운영 Geocoder 장애·한도 응답.
4. **별도 조사:** 운영 첫 분석 약 4.5초 지연 원인. 과거 확대 캡처 불일치와 숨김 전환 원인은 미확정 기록으로 유지한다.
5. **8-D 반경 변경:** 현재 분석은 500m 고정. 지도 확대와 분석 반경 변경을 구분하며, 점수까지 반경을 바꾸는 엔진·정규화·캐시·API 작업은 보류한다.

향후 운영 배포는 구현·검수를 완료한 뒤 별도 단계로 진행한다. 이번 8차 개선의 운영 배포는 수행하지 않았다.
