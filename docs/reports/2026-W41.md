## 3. 작업 영역별 결과

### 3.1 하네스 — 원본 보호와 재현성 (TASKS H-0, D-001 ~ D-008)
- `sources/team_v0.3/` 75개 파일을 해시 매니페스트로 고정하고 매 check에서 검증한다. 원본 `run_all.py`는 실행하지 않는다.
- 엔진은 원본과 **바이트 동일한 사본**(`scoring_engine/v0_3/`)으로 두고, 평면 import는 패키지 쪽에서 처리했다 (D-002). 그래서 "같은 엔진"임을 해시로 증명할 수 있다.
- `run_all.py`에 하드코딩된 부평역 좌표·행정동·임대료 상권은 `SiteContext` 파라미터로 분리하고, 입력 조립·후처리는 `service.py`로 옮겼다 (D-003).
- golden = 원본 `05_분석결과` 그대로. 가중치 ±0.01, 병목 기준, 타겟 연령을 일부러 바꾸면 golden이 실패하는 것까지 확인했다 (D-005). golden은 엔진 버전을 올릴 때만 새로 만든다 (D-006).

### 3.2 Analysis Context Builder — 좌표를 엔진 입력으로 (TASKS 1, D-009 ~ D-011, D-015, D-017)
- 행정동 경계: 2026-07-01 기준 인천 158개 동을 직접 사용 (2026-07 행정구역 개편으로 분동된 운서·아라동 때문에 2024 경계 + crosswalk로는 판정 불가). 경계 코드 158개 = 런타임 패널 158개.
- `LocationResolver`: 좌표 → 행정동·시군구 (point-in-polygon). 인천 밖·바다·잘못된 좌표는 각각 다른 오류.
- `ContextBuilder`: 좌표 → `SiteContext`. 반경 500m 안에 점포가 없으면 분석을 거부(`no_data_nearby`).
- 검증: 점포 135,750개 전수를 resolver로 판정해 점포의 행정동 라벨과 비교, 구별 floor와 동 단위 과반 안전망을 테스트로 고정 (D-010).
- **구월 경계 교정**: 구월3동 라벨 점포 2,486개가 경계상 구월1동으로 판정되는 충돌을 발견. SGIS 공식 역지오코딩으로 439개 좌표 모두 구월3동임을 확인 → 2차 가공 경계가 2015년 편입을 반영하지 못한 것. SGIS 2025 공식 polygon으로 두 동만 교정했다 (D-017). 엔진·런타임 데이터·golden은 바뀌지 않았다.
- 임대료 상권(R-ONE 9곳)은 MVP에서 일반 좌표에 연결하지 않기로 결정 (D-015). 모든 좌표에서 안정성 S4는 "데이터 없음"으로 제외되고 엔진 규칙대로 재정규화된다.

### 3.3 성능 (TASKS 2, D-013, D-016)
- 데이터 로드 약 4s, 업종 1개 비교 모집단 계산 약 2.5s, 29개 전체 약 60s.
- 서버는 데이터 로드 직후 요청을 받고, 29개 업종 warm은 background에서 진행 (`/health`에 진행도). warm 후 분석 응답 약 0.03s.
- reference 디스크 캐시는 현재 성능으로 충분해 **미도입** (멀티 워커·잦은 재시작이 생기면 재검토).

### 3.4 Backend — FastAPI (TASKS 3, D-012, D-014)
- `GET /health`, `GET /businesses`(29개 업종·4개 그룹, 엔진 `config` 그대로), `POST /analyze`.
- 엔진 결과는 가공 없이 그대로 전달한다. API 결과 == `AnalysisService` 직접 호출 결과임을 pass-through 테스트로 고정.
- 오류 계약: 사용자 입력·분석 불가는 422 + `error.code`(`invalid_request`, `invalid_coordinate`, `location_outside`, `no_data_nearby`, `invalid_business`, `invalid_analysis_options`), 내부 오류는 500 + `request_id`(traceback은 서버 로그에만).

### 3.5 Frontend — React + TypeScript (TASKS 4)
- 구현 전에 `DESIGN.md`로 디자인 시스템(색·타이포·결과 위계·오류 상태·반응형·접근성)을 먼저 확정했다.
- API 응답 타입은 Zod 스키마에서 추론하고, golden JSON 29개가 스키마를 통과하는지 테스트한다.
- 화면: NAVER Maps 위 위치 선택(클릭·좌표 입력, 반경 500m 원) → 업종 선택 → 결과(종합 점수, 5대 관점, 병목·주의, 데이터 충족률, 세부지표, 출처) → 분석된 행정동 경계 강조. `error.code`별 안내 화면.
