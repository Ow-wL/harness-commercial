## B. D-022 초안 (승인 전 — DECISIONS.md에 아직 넣지 않음)

> **## D-022 지도 범위 맞춤: 위치·반경이 바뀌면 분석 범위가 사용 가능한 지도 영역에 맞게 보인다 (초안, 8차)**
>
> - 결정(안): 새 위치 선택·반경 변경·비교 B 선택 때 반경 원(비교는 A∪B)이 **사용 가능 영역 U**(지도 사각형 − 우리 오버레이 − SDK 컨트롤) 안에 들어가고, 단일이면 지름이 U 짧은 변의 절반 이상이 되도록 zoom과 중심을 옮긴다. 사용자가 직접 확대·이동하면 같은 지점·반경에서는 다시 맞추지 않는다. 점포 선택·분석 완료·화면 전환·창 크기 변경은 zoom을 바꾸지 않는다.
> - 대체하는 문장(승인 시 함께 고침): D-019 "지도 확대 수준은 바꾸지 않는다(초기 zoom 11에서는 점포 마커가 겹쳐 보인다 — 목록·확대로 본다)." · D-020 "자동 확대·'두 위치 모두 보기'는 하지 않는다(D3)" 중 해당 부분 · `COMPARE_DESIGN.md` D3 · DESIGN.md §8.15 "zoom 유지, 자동 확대 없음" · `MapView.test.tsx`의 `setZoom` 미호출 단언(정책 테스트로 교체). D-019의 나머지(별도 API·점포 수 대조)와 D-020의 나머지는 그대로.
> - 우선순위(위가 이긴다):
>
> | 순위 | 사건 | 동작 | 잠금 |
> |---|---|---|---|
> | 1 | "범위에 맞추기" / "두 위치 모두 보기" | 무조건 맞춤 | 해제 |
> | 2 | 새 위치 선택 | 이미 완료 조건이면 이동 없음, 아니면 맞춤 | 해제 |
> | 3 | 반경 변경 | 2와 같음 | 해제 |
> | 4 | 숨김 복귀 | 미뤄 둔 2·3만 1회 | 유지 |
> | 5 | B 선택 | A∪B 맞춤 zoom ≥ 13이면 A∪B, 아니면 B 원 + "두 위치 모두 보기" | 해제 |
> | 6 | A↔B 전환·비교 종료 | 조건을 만족하면 `panTo`, 아니면 맞춤. 잠금 중이면 `panTo`만 | 유지 |
> | 7 | 사용자 휠·드래그·± | 잠금 | 켬 |
> | 8 | 점포 선택·분석 완료·화면 전환·resize | zoom 변경 없음 | 유지 |
>
> - 완료 조건: 단일 = 원 bbox ⊂ U 이고 지름 ≥ 0.5 × min(U). 비교(zoom ≥ 13) = 두 원 ⊂ U. 비교(멂) = B 원 단일 조건 + 버튼. 점포 선택·Escape·크기 변경 20회 뒤 zoom 불변. **우리 오버레이가 NAVER 로고·축척(켠 경우 저작권 표기)과 겹치지 않음.** 판정은 원 SVG 요소 사각형, 교차 확인은 `getBounds` 계산. production build 1280·970·800×600·375·360에서 확인.
> - 확대 컨트롤: SDK `zoomControlOptions.style = SMALL`(검수 결정 2026-10-14).
> - 구현 단계: 8-B1 단일(순위 1의 '범위에 맞추기'·2·4·7·8), 8-B2 비교(순위 1의 '두 위치 모두 보기'·5·6, 비교 숨김 복귀).
> - 구현 수단 — 단일 원(8-B0 실측 2026-10-13, 재측정 2026-10-14): `z = clamp(지금 zoom + floor(log2(min(U.w, U.h) / d)), minZoom, maxZoom)`(d = 지금 zoom의 원 지름 px) 후 `setCenter(원 중심)` → `setZoom(z, false)` → `panBy(Point(지도 중심.x − U 중심.x, 지도 중심.y − U 중심.y))`(모두 동기; `panBy(+x,+y)`는 원을 화면에서 왼쪽·위로 옮긴다). 18개 조합에서 완료 조건 충족, 원 중심 = U 중심. **비교(A∪B)는 8-B0에서 SDK `fitBounds`만 측정했고 직접 계산은 미검증 — 8-B2에서 정한다.** SDK `fitBounds(bounds, margin)`의 zoom 선택은 쓰지 않는다 — 비대칭 margin에서 각 축 큰 margin을 양쪽에 둔 것처럼 한 단계 낮은 zoom을 골라 1280·375의 일부 반경에서 완료 조건 미달(43~49%). 사용자 조작 감지는 SDK `zooming`·`dragstart`(우리 호출은 내지 않음). `panTo` 진행 중 `setZoom`은 이동을 중간에서 멈추므로 이동·맞춤 중 하나만 고른다. 숨김(0×0) 중에는 SDK가 이전 크기로 계산하고 U를 잴 수 없으므로 미뤘다가 보이고 `setSize`한 뒤 1회(6-4 흐름). `fromCoordToOffset`은 `panBy` 뒤 갱신되지 않아 측정에 쓰지 않는다. 재현: `docs/spikes/8-B0/`.
> - 이유: z11에서 500m 원이 지름 약 16px로 점처럼 보여 선택 위치·범위·점포를 함께 읽을 수 없었다(P1). 화면이 튀는 문제는 "사건별 우선순위 + 사용자 잠금 + resize·점포 선택 불변"으로 막는다.
> - 미검증: 실제 입력(isTrusted) 휠·드래그·터치 pinch가 `zooming`/`dragstart`를 내는지, 실제 모바일 기기(8-B1 브라우저 확인). A∪B 직접 계산, 숨김 중 B 선택·맞춤 버튼 요청의 미루기(8-B2).
> - 검증: MapView 단위 테스트(사건 8개 × 잠금 상태), production build 5개 폭 실측, 20회 반복 zoom 불변, SDK 로고·축척 가림 없음(사각형 교차 0), 기존 6-4(숨김 정보창)·B1(panTo) 테스트 유지.
